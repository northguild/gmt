<Fragment slot="keypoint">

A Code B day is a count from 1 January, so every date after February moves by one in a leap year.

<Fragment slot="intro">

CCSDS Code B writes a UTC date as a year and a day number, such as `2024-061`. Pick two years and a day: the tool reads the day in each with [`parseCcsdsAsciiB`](/reference/timescale/parse/parseCcsdsAsciiB/), writes it back with [`formatCcsdsAsciiA`](/reference/timescale/format/formatCcsdsAsciiA/), and finds where each month starts with [`formatCcsdsAsciiB`](/reference/timescale/format/formatCcsdsAsciiB/). To read a whole code, use the [CCSDS Time Code Decoder](/tools/ccsds-time-code-decoder/).

</Fragment>

<Fragment slot="after">

**Day of year, not month.** Day 061 is 1 March in 2024 and 2 March in 2026, because 2024 has a 29 February and 2026 does not. Every date after February moves by one day between a leap year and a common year, so a Code B text names no fixed month and day. Days 1 to 59 do not move: `2024-059` and `2026-059` are both 28 February. The ruler puts both years on one scale of 366 day columns, so each month after February starts a column further left in a leap year.

**Day 366.** Only a leap year has one. `2016-366` is 31 December 2016, and the library refuses `2017-366`. The ruler draws that last column hatched and labelled `no day 366` in a year that lacks it.

**Leap years come from the library.** The tool holds no leap-year rule and no table of month lengths. It asks `parseCcsdsAsciiB` whether a year has a day 366, and `formatCcsdsAsciiB` for the day each month starts on. So 2000 has a 29 February and 2100 does not: day 060 is 29 February in 2000 and 1 March in 2100. A year the library cannot read, such as 10000, shows `no result` beside a lane that still works.

```ts
import { parseCcsdsAsciiB } from "@northguild/gmt/timescale/parse";
import { formatCcsdsAsciiA } from "@northguild/gmt/timescale/format";

formatCcsdsAsciiA(parseCcsdsAsciiB("2024-061T00:00:00Z"), 0); // "2024-03-01T00:00:00Z"
formatCcsdsAsciiA(parseCcsdsAsciiB("2026-061T00:00:00Z"), 0); // "2026-03-02T00:00:00Z"
parseCcsdsAsciiB("2017-366T00:00:00Z"); // ""
```
