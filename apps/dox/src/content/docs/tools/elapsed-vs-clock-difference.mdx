<Fragment slot="keypoint">

Subtract two UTC readings and you get the clock difference. Count the seconds that passed and you get the elapsed time. They differ by every second inserted in between.

</Fragment>

<Fragment slot="intro">

A UTC day normally has 86400 seconds. On a day with an inserted second it has 86401, and the extra one is written `23:59:60`. Subtracting two UTC readings treats every day as 86400 seconds long, so it skips the inserted ones. Counting through TAI, which never inserts a second, gives the time that really passed.

Type a start and an end, or pick a preset. The two rulers draw the same span: the top one as the clock reads it, the bottom one as the elapsed time, with each inserted second as a hatched sliver. Under them are the three results and the exact calls. Drag the slider to move the end a day at a time.

</Fragment>

<Fragment slot="after">

**The clock difference.** [`spanNs`](/reference/span/calculate/spanNs/) subtracts two UTC readings and returns nanoseconds as a `bigint`. It has no answer for a `23:59:60`, because the clock method has no place to put that second, and the tool shows that as `NO SIGNAL` with the reason.

**The elapsed time.** [`toTAI`](/reference/timescale/convert/toTAI/) turns each UTC reading into a TAI reading, and `spanNs` of the two TAI readings is the time that passed. A second 60 is fine here, so a span that starts on the leap second still has an answer. Before 1972-01-01 UTC and TAI did not differ by whole seconds, so the library returns an empty answer and the tool shows `NO SIGNAL`.

**The count.** [`leapSecondsBetween`](/reference/timescale/calculate/leapSecondsBetween/) counts the seconds inserted between the two readings, and it is negative when the end comes first. Zero is a real answer: no second was inserted between the two, so both methods agree.

```ts
spanNs("2016-12-31T23:59:59Z", "2017-01-01T00:00:01Z"); // 2000000000n
toTAI("2016-12-31T23:59:59Z"); // "2017-01-01T00:00:35 TAI"
toTAI("2017-01-01T00:00:01Z"); // "2017-01-01T00:00:38 TAI"
leapSecondsBetween("2016-12-31T23:59:59Z", "2017-01-01T00:00:01Z"); // 1
leapSecondsBetween("2020-01-01T00:00:00Z", "2024-01-01T00:00:00Z"); // 0
```
