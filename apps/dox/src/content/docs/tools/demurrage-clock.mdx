<Fragment slot="keypoint">

Demurrage and detention share one event and nothing else. Demurrage ends at the gate-out, and detention starts there.

</Fragment>

<Fragment slot="intro">

A container's charges run on clocks, and each clock runs between two of its events. Demurrage runs while the container is inside the terminal. Detention runs while it is outside. Storage is the charge for the terminal's space, and the merged clock runs demurrage and detention as one period.

List the events, choose the leg and the clock, and the tool calls [`demurrageClock`](/reference/intermodal/calculate/demurrageClock/) once for each of the four clocks. The chosen clock is lit and the other three are dimmed. A clock the library cannot read keeps its row and says why in words. The tool does not hold a table of which events go with which clock: it asks the library, with one event of each type, and reads the pair back.

</Fragment>

<Fragment slot="after">

**The rule.** The same clock runs between different events on the import leg and the export leg, so the direction has no default. The library does not guess it from the events. An event recorded twice is a data error and not a choice, so every clock that needs it returns `null`. A clock that ends before it starts returns `null` too. The result is half-open: it starts at the first event and stops just before the second.

**The terminal clock is a display zone, not an argument.** The zone you pick sets the day columns and the local times on the chips and plates. It is not passed to `demurrageClock`, which returns your own strings unchanged. Change the zone and the days move, but the intervals do not.

```ts
const events = [
  { type: "discharged", at: "2024-06-14T19:00:00Z" },
  { type: "available", at: "2024-06-15T12:00:00Z" },
  { type: "gatedOut", at: "2024-06-20T14:30:00Z" },
  { type: "emptyReturned", at: "2024-06-27T09:00:00Z" },
];

demurrageClock(events, "demurrage", { direction: "import" }); // { start: "2024-06-14T19:00:00Z", end: "2024-06-20T14:30:00Z" }
demurrageClock(events, "detention", { direction: "import" }); // { start: "2024-06-20T14:30:00Z", end: "2024-06-27T09:00:00Z" }
demurrageClock(events, "storage", { direction: "import" }); // { start: "2024-06-14T19:00:00Z", end: "2024-06-20T14:30:00Z" }
demurrageClock(events, "combined", { direction: "import" }); // { start: "2024-06-14T19:00:00Z", end: "2024-06-27T09:00:00Z" }
```

**How long it ran.** `demurrageClock` returns the strings you gave it, and [`diffUtcAsDuration`](/reference/utc/calculate/diffUtcAsDuration/) reads `Z` instants only. So the tool passes each end through [`toOffsetInstant`](/reference/instant/convert/toOffsetInstant/) first, then measures between the two. The demurrage example above ran for `PT139H30M`, which the plate shows as 5 d 19 h 30 min.

**Count the days.** The link under the chart sends the chosen clock, as the library returned it, to the [Free Time Ledger](/tools/free-time-ledger/) with the terminal clock. There you set the free days and see which days are charged. The rules are in [Intermodal: Free Time and Demurrage](/guides/industries/intermodal-free-time-and-demurrage/).
