<Fragment slot="keypoint">

A METAR time names a day but no month, so it needs a reference. A NOTAM time names the whole date, and `PERM` is not a date.

<Fragment slot="intro">

A weather report writes its time as `DDHHMMZ`, such as `302350Z`. There is a day, an hour and a minute, and no month. To read it you need a reference: the time you received the report, or another time you trust. A NOTAM is different. Items B) and C) carry the year, the month and the day, in a two-digit year that needs a window, and item C) can be `PERM` or end in `EST`.

Section 1 reads a group against a reference you type and draws the candidate months on a strip. A slider moves the reference across a month end. Section 2 reads items B) and C) in a window you state. Every instant, month, gap and distance on the page is a library result, and each section prints the calls it made.

</Fragment>

<Fragment slot="after">

**METAR reads.** [`parseMetarTime`](/reference/aviation/parse/parseMetarTime/) takes the group and the reference you state, and returns the instant of the nearest month that has the day. A tie goes to the earlier. It never reads the clock, so the same report gives the same answer in any month.

**METAR valid.** [`isValidMetarTime`](/reference/aviation/validate/isValidMetarTime/) is true exactly when the read returns an instant. With no reference it is false, because a group alone is not a time.

**NOTAM reads.** [`parseNotamValidity`](/reference/aviation/parse/parseNotamValidity/) reads a ten-digit item as an instant in the window you state, reads `EST` as an instant that is estimated, and reads `PERM` as a state with no date.

**NOTAM valid.** [`isValidNotamValidity`](/reference/aviation/validate/isValidNotamValidity/) is true exactly when the read returns a result. With no window it is false for every item, `PERM` included.

**The strip.** The seven slots are the months around the answer, from three back to three forward. Each one is [`addUtc`](/reference/utc/calculate/addUtc/) with `overflow: "reject"`, so a month without the day is a gap and not a shifted date. The chosen candidate is the one equal to the library's answer, and the page marks it with a ring as well as a colour.

See [Aviation message times](/guides/industries/aviation-message-times/), [a METAR from last month](/scenarios/a-metar-from-last-month/), [PERM read as a date](/scenarios/perm-read-as-a-date/) and [Aviation mistakes](/mistakes/aviation/). The time formats follow WMO and EUROCONTROL OPADD.

**Worth trying:**

- [A report across a month end](/tools/report-time-resolver/?w=reporttime&wa=%7B%22metarPreset%22%3A%22month-end%22%7D) — `302350Z` received just after midnight on 1 July reads as 30 June, not July.
- [31 near February](/tools/report-time-resolver/?w=reporttime&wa=%7B%22metarPreset%22%3A%22february-31%22%7D) — `312359Z` at 1 March: February has no 31st, so the strip shows a gap and the answer is 31 January.
- [Equally near](/tools/report-time-resolver/?w=reporttime&wa=%7B%22metarPreset%22%3A%22tie%22%7D) — two candidates sit the same time from the reference. A tie goes to the earlier.
- [A reference with an offset](/tools/report-time-resolver/?w=reporttime&wa=%7B%22metarPreset%22%3A%22offset-reference%22%7D) — months are counted in UTC, so a reference of `00:05+02:00` on 1 July is still on 30 June.
- [No reference](/tools/report-time-resolver/?w=reporttime&wa=%7B%22metarPreset%22%3A%22no-reference%22%7D) — a report time names no month, so with no reference nothing is read, and the page says why.
- [An estimated end](/tools/report-time-resolver/?w=reporttime&wa=%7B%22notamPreset%22%3A%22opadd-estimate%22%7D) — `1407031230EST` is an instant that is estimated, not a different kind of value.
- [Permanent](/tools/report-time-resolver/?w=reporttime&wa=%7B%22notamPreset%22%3A%22permanent%22%7D) — `PERM` is a state with no date, shown as "permanent, no date" and not as a far-future instant.
- [No window](/tools/report-time-resolver/?w=reporttime&wa=%7B%22notamPreset%22%3A%22no-window%22%7D) — nothing says which century `25` is, so with no window there is no date, and `PERM` is refused too.
- [EST in item B)](/tools/report-time-resolver/?w=reporttime&wa=%7B%22notamPreset%22%3A%22est-in-b%22%7D) — the library reads it, and a note says OPADD allows `EST` in item C) only.
- [Write the end of a day as 2400](/tools/report-time-resolver/?w=reporttime&wa=%7B%22notamPreset%22%3A%22end-2400%22%7D) — `2506152400` is refused: OPADD writes the end of a day as 2359.
