<Fragment slot="keypoint">

Every handoff is an exact instant, never a wall-clock guess. One leg's arrival, plus its handling time, becomes the next leg's departure.

</Fragment>

<Fragment slot="intro">

Each leg is a departure, a duration and the zone it lands in. The summary
card leads with the ETA in the last leg's own zone, the door-to-door span, and
flags for what happened along the way: a DST change, a Date Line crossing, or a
handoff an offset table would get wrong. An offset table is a fixed UTC offset
looked up for each place, with no DST. A missed connection turns the same card into a
failure state naming the leg.

A toggle switches between two charts of the same journey. **Route** draws one
segment per leg, never sized by how long the leg took. **To scale** draws the
same legs on a real time axis. Where an offset table would misread a handoff,
both charts flag it. That offset-table reading is the only value the widget
computes itself, and it is always labelled naive. Everything else is the
real [`scheduleDelivery`](/reference/transport/calculate/scheduleDelivery/) call for what is on screen.

</Fragment>

**Moving and waiting.** The field called _Handling after_ is the time the cargo needs at a handoff before the next leg may leave. The link at the end of the third section, _Split this journey into moving and waiting_, opens the same legs in the [Journey Split](/tools/journey-split/), which sorts the hours into the time the cargo moves and the time it waits. [The first preset there](/tools/journey-split/?w=journeysplit&wa=%7B%22legCount%22%3A%223%22%2C%22departure1%22%3A%222024-03-29T08%3A00%3A00%2B01%3A00%5BEurope%2FBerlin%5D%22%2C%22duration1%22%3A%22PT44H%22%2C%22timeZone1%22%3A%22Europe%2FLondon%22%2C%22dwellAfter1%22%3A%22PT2H%22%2C%22mode1%22%3A%22truck%22%2C%22duration2%22%3A%22P11D%22%2C%22timeZone2%22%3A%22Asia%2FTokyo%22%2C%22dwellAfter2%22%3A%22PT24H%22%2C%22mode2%22%3A%22ship%22%2C%22duration3%22%3A%22PT2H30M%22%2C%22timeZone3%22%3A%22Asia%2FTokyo%22%2C%22mode3%22%3A%22rail%22%7D) moves for `PT310H30M` and waits `PT26H`: the 2 hours and the 24 hours of handling.
