---
title: Type Conversion
description: Common mistakes when converting between date/time types with GMT.
---

GMT provides conversion functions between plain, zoned, UTC, Unix, and calendar
types. The mistakes here cover unit mismatches, annotation handling, and calendar
semantics.

## Mistakes

import Mistake from "../../../components/Mistake.astro";

<Mistake
  severity="high"
  title="Using Date.getTime() for conversion"
  description="Date.getTime() returns epoch milliseconds whatever the consumer expects. Handing that number to an API that expects Unix seconds introduces a 1000× unit error. GMT's conversions name the unit: milliseconds by default, seconds when you pass 'seconds'."
  wrongCode={`const ms = new Date("2024-03-15").getTime(); // 1710460800000 — milliseconds
const unix = ms; // used as seconds — 1000× too large`}
  rightCode={`import { convertUtcToUnix } from "@northguild/gmt/utc";

convertUtcToUnix("2024-03-15T00:00:00Z"); // 1710460800000 — milliseconds (the default)
convertUtcToUnix("2024-03-15T00:00:00Z", "seconds"); // 1710460800 — seconds, named`}
/>

<Mistake
  severity="high"
  title="Mixing epoch seconds and milliseconds"
  description="getUnixNow() returns milliseconds; getUnixNow('seconds') returns seconds. Passing seconds to a function expecting milliseconds (or vice versa) produces timestamps that are 1000× off."
  wrongCode={`const ts = getUnixNow("seconds"); // 1710504645 — seconds
const asMs = ts * 1000; // manual conversion — error-prone`}
  rightCode={`import { getUnixNow } from "@northguild/gmt/unix";

getUnixNow(); // 1710504645000 — milliseconds (the default)
getUnixNow("seconds"); // 1710504645 — seconds
// ask for the unit the consumer expects`}
/>

<Mistake
  severity="medium"
  title="Not handling conversion errors"
  description="Conversion functions return a sentinel for invalid input rather than throwing — an empty string from a function that returns a string, null from one that returns a number, such as convertUtcToUnix. A failed conversion is silent — check the result."
  wrongCode={`const result = convertUtcToUnix(badInput); // null`}
  rightCode={`import { convertUtcToUnix } from "@northguild/gmt/utc";

const result = convertUtcToUnix(input);
if (result === null) {
  // input was invalid
}`}
/>

<Mistake
  severity="medium"
  title="Assuming a [u-ca=...] string means Temporal's own convention"
  description="GMT's convertDateToCalendar and convertZonedToCalendar write the calendar's own year, month and day in front of the [u-ca=...] annotation. Temporal's own serialization keeps the ISO digits there, so Temporal cannot read GMT's string back as the same date. Convert back with GMT instead."
  wrongCode={`Temporal.PlainDate.from("0006-03-15[u-ca=japanese;era=reiwa]"); // throws RangeError — not Temporal's convention`}
  rightCode={`import { convertDateToCalendar } from "@northguild/gmt";

convertDateToCalendar("2024-03-15", "japanese"); // "0006-03-15[u-ca=japanese;era=reiwa]"
convertDateToCalendar("0006-03-15[u-ca=japanese;era=reiwa]", "gregorian"); // "2024-03-15"`}
/>

<Mistake
  severity="medium"
  title="Assuming 'japanese''s annotated year is proleptic like every other calendar"
  description="The Japanese calendar uses era-based years. Reiwa 6 is not proleptic Gregorian year 2024 — it is era year 6. Do not add 2018 to convert: that offset is only right inside the Reiwa era."
  wrongCode={`const jy = convertDateToCalendar("2024-03-15", "japanese").slice(0, 4); // "0006" — the era year
const gregorianYear = Number(jy) + 2018; // right for Reiwa only`}
  rightCode={`// The annotated year is the era year; convert back through GMT for the Gregorian date
convertDateToCalendar("2024-03-15", "japanese"); // "0006-03-15[u-ca=japanese;era=reiwa]"
convertDateToCalendar("0006-03-15[u-ca=japanese;era=reiwa]", "gregorian"); // "2024-03-15"`}
/>

<Mistake
  severity="medium"
  title="Assuming 'ethiopic''s annotated year is a fixed offset"
  description="The Ethiopic calendar year is approximately 7-8 years behind the Gregorian year, but the offset varies because the calendars have different leap-year rules. Do not use a fixed subtraction."
  wrongCode={`const ethYear = gregYear - 8; // fixed offset — inaccurate near leap years`}
  rightCode={`import { convertDateToCalendar } from "@northguild/gmt";

convertDateToCalendar("2024-03-15", "ethiopic"); // "2016-07-06[u-ca=ethiopic;era=ethiopic]"`}
/>
