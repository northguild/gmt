---
title: Duration
description: Common mistakes when working with durations in GMT.
---

The `duration/` functions take ISO 8601 duration strings; the `add*`/`subtract*`
functions take unit objects. Confusing the two representations is the most common
source of duration bugs.

## Mistakes

import Mistake from "../../../components/Mistake.astro";

<Mistake
  severity="high"
  title="Confusing duration strings with unit objects"
  description="'P1Y2M' and `{ years: 1, months: 2 }` are not interchangeable. Duration functions take an ISO 8601 duration string; add and subtract functions take a unit object. Passing the other shape returns the invalid-input sentinel."
  wrongCode={`normalizeDuration({ years: 1, months: 2 }); // "" — a unit object, not a duration string
addDate("2024-01-15", "P1Y2M"); // "" — a duration string, not a unit object`}
  rightCode={`import { addDate, formatDuration } from "@northguild/gmt";

formatDuration("P1Y2M", "en-US"); // "1 year and 2 months"
addDate("2024-01-15", { years: 1, months: 2 }); // "2025-03-15"`}
/>

<Mistake
  severity="medium"
  title="Not validating before parsing"
  description="parseDuration returns an empty string for invalid input. Feeding unvalidated user input straight into duration arithmetic produces silent failures."
  wrongCode={`const d = parseDuration(userInput); // userInput = "PX" → "" — no error thrown`}
  rightCode={`import { isValidDuration, parseDuration } from "@northguild/gmt";

if (isValidDuration(userInput)) {
  const d = parseDuration(userInput);
}`}
/>

<Mistake
  severity="medium"
  title="Expecting a best-effort answer for calendar units without relativeTo"
  description="Converting a calendar-unit duration (years, months) to days requires a reference date. Without `relativeTo`, the conversion is ambiguous — different months have different lengths."
  wrongCode={`durationAs("P1M", "days"); // null — 28, 29, 30 or 31 days: without relativeTo, which month?`}
  rightCode={`import { durationAs } from "@northguild/gmt";

durationAs("P1M", "days", { relativeTo: "2024-02-01" }); // 29 — February 2024 is a leap month`}
/>

<Mistake
  severity="high"
  title="Reading a component with getDurationUnit when you wanted a total"
  description="getDurationUnit returns one component of a normalized duration (e.g. just the hours). If you need the total duration in a specific unit, use durationAs instead."
  wrongCode={`const d = normalizeDuration("P1DT2H3M");
const hours = getDurationUnit(d, "hours"); // 2 — just the hours component, not the total`}
  rightCode={`import { normalizeDuration, durationAs } from "@northguild/gmt";

const d = normalizeDuration("P1DT2H3M");
const totalHours = durationAs(d, "hours"); // 26.05 — full duration converted, 3 minutes included`}
/>

<Mistake
  severity="medium"
  title="Expecting normalizeDuration to resolve calendar units against today"
  description="normalizeDuration has no implicit relativeTo. Whenever a calendar unit (years, months, weeks) is involved, in the duration or as largestUnit, it needs an explicit `relativeTo`; without one it returns the empty-string sentinel, never a conversion against today's date."
  wrongCode={`normalizeDuration("P1M", { largestUnit: "day" }); // "" — no relativeTo, so no answer`}
  rightCode={`import { normalizeDuration } from "@northguild/gmt";

normalizeDuration("P1M", { largestUnit: "day", relativeTo: "2024-02-01" }); // "P29D"`}
/>

<Mistake
  severity="medium"
  title="Expecting formatDuration to match native Intl.DurationFormat output exactly"
  description="GMT's formatDuration renders each non-zero component with Intl.NumberFormat's unit style and joins them with Intl.ListFormat. Intl.DurationFormat output varies by locale, unit set, and style options in its own way. They are not drop-in replacements for each other."
  wrongCode={`// assuming formatDuration("PT1H30M") matches Intl.DurationFormat`}
  rightCode={`import { formatDuration } from "@northguild/gmt";

formatDuration("PT1H30M", "en-US"); // "1 hour and 30 minutes" — joined as a list`}
/>

<Mistake
  severity="medium"
  title="Passing an array of units to durationAs"
  description="durationAs takes a single unit name, not an array. Passing a list of unit names returns null."
  wrongCode={`durationAs("P1DT2H3M", ["hours", "minutes"]); // null — expects a single unit string`}
  rightCode={`import { durationAs } from "@northguild/gmt";

durationAs("P1DT2H3M", "hours"); // 26.05
durationAs("P1DT2H3M", "minutes"); // 1563 — one call per unit`}
/>
