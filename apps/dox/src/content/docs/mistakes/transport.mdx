---
title: Transport
description: Common mistakes with transit legs, arrivals and dwell in GMT's transport layer.
---

The transport layer is `transitTime`, `etaAtZone`, `dwellTime`, `scheduleDelivery` and
`crossingTime`, and the mistakes around them are the ones every transport mode makes on its
own: treating a running time as a wall-clock interval, treating an offset as a place, turning
elapsed hours into chargeable days by division, reading a handoff through a fixed offset, and
checking a connection against the arrival instead of the arrival plus its handling time. Every
output shown here is what the function returns.

## Legs and dwell

import Mistake from "../../../components/Mistake.astro";

<Mistake
  severity="high"
  title="Dividing dwell hours by 24 to get chargeable days"
  description="Terminals count the local calendar days a container was present, not elapsed time rounded up. Two hours across a local midnight is two days. dwellTime returns calendarDays from the zone's real day boundaries; the duration is there too, for a different question."
  wrongCode={`const hours = 2; // gated in 23:00, out 01:00
Math.ceil(hours / 24);
// 1 — the terminal bills 2`}
  rightCode={`import { dwellTime } from "@northguild/gmt/transport";

dwellTime("2024-06-15T23:00:00-04:00[America/New_York]", "2024-06-16T01:00:00-04:00[America/New_York]");
// { duration: "PT2H", enter: "2024-06-15T23:00:00-04:00[America/New_York]", exit: "2024-06-16T01:00:00-04:00[America/New_York]", calendarDays: 2 }`}
  rightSpecId="dwellTime"
/>

<Mistake
  severity="high"
  title="Counting dwell days from bare instants with no zone"
  description="A day count needs a place. Z and offset-only strings name a moment and nothing else, so with no targetZone there is no locality to count days in and dwellTime returns null rather than guessing. Pass the IANA zone of the terminal, or use entry strings that carry one."
  wrongCode={`dwellTime("2024-06-16T03:00:00Z", "2024-06-16T05:00:00Z");
// null — no place to count days in`}
  rightCode={`import { dwellTime } from "@northguild/gmt/transport";

dwellTime("2024-06-16T03:00:00Z", "2024-06-16T05:00:00Z", "America/New_York").calendarDays; // 2
dwellTime("2024-06-16T03:00:00Z", "2024-06-16T05:00:00Z", "Europe/Amsterdam").calendarDays; // 1`}
/>

<Mistake
  severity="high"
  title="Adding a running time as a wall-clock duration"
  description="addZoned moves the wall clock by the date part of a duration, which is right for a recurring meeting and wrong for a running time. Across a spring-forward, one day and two hours on the wall clock is 25 elapsed hours. transitTime adds exact time, so P1DT2H is 26 hours and the arrival is an hour later, when the train is actually there."
  wrongCode={`addZoned("2024-03-09T20:00:00-05:00[America/New_York]", { days: 1, hours: 2 });
// "2024-03-10T22:00:00-04:00[America/New_York]" — only 25 elapsed hours`}
  rightCode={`import { transitTime } from "@northguild/gmt/transport";

transitTime("2024-03-09T20:00:00-05:00[America/New_York]", "P1DT2H");
// "2024-03-10T23:00:00-04:00[America/New_York]" — 26 elapsed hours`}
  rightSpecId="transitTime"
/>

<Mistake
  severity="medium"
  title="Giving transitTime a calendar duration"
  description="Years, months and weeks have no fixed length, and a leg is measured in elapsed time, so transitTime returns the empty string for them rather than picking a month length. A dated connection, the same wall time a month on, is addZoned's job."
  wrongCode={`transitTime("2024-06-15T10:00:00Z", "P1M");
// "" — no leg takes "a month" without a reference point`}
  rightCode={`import { addZoned } from "@northguild/gmt/zoned";

addZoned("2024-06-15T10:00:00+02:00[Europe/Berlin]", { months: 1 });
// "2024-07-15T10:00:00+02:00[Europe/Berlin]"`}
/>

<Mistake
  severity="high"
  title="Carrying last winter's offset into a summer departure"
  description="A bracketed zone whose offset contradicts it is rejected, not reinterpreted: New York is -04:00 in June, so a departure written -05:00[America/New_York] is not a moment the zone ever showed, and transitTime returns the empty string as isValidZonedDateTime does. Write the offset the zone kept at that moment, or drop the bracket and keep only the offset if that is really all you know."
  wrongCode={`transitTime("2024-06-15T10:00:00-05:00[America/New_York]", "PT2H");
// "" — the offset contradicts the zone`}
  rightCode={`import { transitTime } from "@northguild/gmt/transport";

transitTime("2024-06-15T10:00:00-04:00[America/New_York]", "PT2H");
// "2024-06-15T12:00:00-04:00[America/New_York]"`}
/>

<Mistake
  severity="medium"
  title="Rendering an arrival in a fixed offset instead of the destination's zone"
  description="etaAtZone accepts a fixed offset as a zone, as Temporal does, but an offset observes no DST. On the fall-back night the destination is still on -04:00 for the first arrival and already on -05:00 for the second, so a fixed -05:00 shows the first an hour early (00:30 instead of 01:30). The second comes out right only because New York has just moved to -05:00, and all summer every arrival shows an hour early. GMT does not resolve an airport code to a zone, so pass the IANA identifier."
  wrongCode={`etaAtZone("2024-11-03T05:30:00Z", "-05:00");
// "2024-11-03T00:30:00-05:00[-05:00]" — New York was still on EDT; the board is an hour early`}
  rightCode={`import { etaAtZone } from "@northguild/gmt/transport";

etaAtZone("2024-11-03T05:30:00Z", "America/New_York");
// "2024-11-03T01:30:00-04:00[America/New_York]"`}
  rightSpecId="etaAtZone"
/>

<Mistake
  severity="medium"
  title="Passing a zoneless wall time as an arrival"
  description="etaAtZone renders a moment, and a datetime with no offset designator is not a moment. It returns the empty string rather than assuming UTC. Resolve the local time to an instant first with resolveLocal or convertPlainDateTimeToZoned, stating the zone it was read in."
  wrongCode={`etaAtZone("2024-06-15T12:30:00", "Asia/Tokyo");
// "" — no offset: not a moment`}
  rightCode={`import { etaAtZone } from "@northguild/gmt/transport";

etaAtZone("2024-06-15T12:30:00Z", "Asia/Tokyo");
// "2024-06-15T21:30:00+09:00[Asia/Tokyo]"`}
/>

## Multi-leg scheduling

Each of these has a live tool: the [Delivery Scheduler](/tools/delivery-scheduler/), the
[Connection Checker](/tools/connection-checker/), the [Timetable Reader](/tools/timetable-reader/)
and the [Crossing Clock](/tools/crossing-clock/).

<Mistake
  severity="high"
  title="Reading a handoff through an offset table"
  description="A fixed offset is a place's offset at one moment, not a standing fact. Reading an arrival that crosses a DST transition through the offset the table was built with misreads it by an hour. scheduleDelivery reads every handoff as an exact instant, never through a stale offset."
  wrongCode={`// The naive approach: one UTC offset per place, from a table
const OFFSET_HOURS = { "America/Los_Angeles": -8 }; // Los Angeles, as the table was built in winter
const departed = Date.parse("2024-03-08T08:00:00-06:00"); // Chicago, 08:00
const arrived = departed + 46 * 36e5; // 2024-03-10T12:00:00.000Z
const toLocal = (ms) => new Date(ms + OFFSET_HOURS["America/Los_Angeles"] * 36e5).toISOString().slice(0, 16);
toLocal(arrived); // "2024-03-10T04:00" — an hour early: the clocks sprang forward that morning`}
  rightCode={`import { scheduleDelivery } from "@northguild/gmt/transport";

const truck = { departure: "2024-03-08T08:00:00-06:00[America/Chicago]", duration: "PT46H", timeZone: "America/Los_Angeles", dwellAfter: "PT2H", mode: "truck" };
scheduleDelivery([truck]);
// { eta: "2024-03-10T05:00:00-07:00[America/Los_Angeles]",
//   legTimes: [{ arrival: "2024-03-10T12:00:00Z", localArrival: "2024-03-10T05:00:00-07:00[America/Los_Angeles]", dwellAfter: "PT2H", mode: "truck" }] } — 05:00, not 04:00`}
  rightSpecId="scheduleDelivery"
/>

<Mistake
  severity="high"
  title="Checking a connection against the arrival, not the arrival plus handling"
  description="An arrival is not the moment cargo can leave again: the handling time at the handoff, the minimum connect time, still has to pass. scheduleDelivery checks a scheduled departure against the arrival plus that dwell, and a departure inside it is a missed connection, not a comparison between two instants."
  wrongCode={`Date.parse("2024-03-10T13:30:00Z") >= Date.parse("2024-03-10T12:00:00Z");
// true — but the handoff needs two hours, and the ship sails inside it`}
  rightCode={`import { scheduleDelivery } from "@northguild/gmt/transport";

const truck = { departure: "2024-03-08T08:00:00-06:00[America/Chicago]", duration: "PT46H", timeZone: "America/Los_Angeles", dwellAfter: "PT2H", mode: "truck" };
const ship = { departure: "2024-03-10T06:30:00[America/Los_Angeles]", duration: "P11D", timeZone: "Asia/Tokyo", mode: "ship" };
const laterShip = { departure: "2024-03-10T07:30:00[America/Los_Angeles]", duration: "P11D", timeZone: "Asia/Tokyo", mode: "ship" };
scheduleDelivery([truck, ship]); // null — missed
scheduleDelivery([truck, laterShip]);
// { eta: "2024-03-21T23:30:00+09:00[Asia/Tokyo]",
//   legTimes: [{ arrival: "2024-03-10T12:00:00Z", localArrival: "2024-03-10T05:00:00-07:00[America/Los_Angeles]", dwellAfter: "PT2H", mode: "truck" },
//     { arrival: "2024-03-21T14:30:00Z", localArrival: "2024-03-21T23:30:00+09:00[Asia/Tokyo]", dwellAfter: "PT0S", mode: "ship" }] } — half an hour later, made`}
  rightSpecId="scheduleDelivery"
/>

<Mistake
  severity="medium"
  title="Giving a later leg a published local time with no zone"
  description="Only the first leg can be read in startTimeZone. A later scheduled departure must be exact, so write its zone in brackets: 2024-03-10T07:30:00[America/Los_Angeles]."
  wrongCode={`import { scheduleDelivery } from "@northguild/gmt/transport";

const truck = { departure: "2024-03-08T08:00:00-06:00[America/Chicago]", duration: "PT46H", timeZone: "America/Los_Angeles", dwellAfter: "PT2H", mode: "truck" };
const ship = { departure: "2024-03-10T07:30:00", duration: "P11D", timeZone: "Asia/Tokyo", mode: "ship" };
scheduleDelivery([truck, ship]);
// null — leg 2's departure has no offset or zone`}
  rightCode={`import { scheduleDelivery } from "@northguild/gmt/transport";

const truck = { departure: "2024-03-08T08:00:00-06:00[America/Chicago]", duration: "PT46H", timeZone: "America/Los_Angeles", dwellAfter: "PT2H", mode: "truck" };
const ship = { departure: "2024-03-10T07:30:00[America/Los_Angeles]", duration: "P11D", timeZone: "Asia/Tokyo", mode: "ship" };
scheduleDelivery([truck, ship]);
// { eta: "2024-03-21T23:30:00+09:00[Asia/Tokyo]",
//   legTimes: [{ arrival: "2024-03-10T12:00:00Z", localArrival: "2024-03-10T05:00:00-07:00[America/Los_Angeles]", dwellAfter: "PT2H", mode: "truck" },
//     { arrival: "2024-03-21T14:30:00Z", localArrival: "2024-03-21T23:30:00+09:00[Asia/Tokyo]", dwellAfter: "PT0S", mode: "ship" }] }`}
  rightSpecId="scheduleDelivery"
/>

<Mistake
  severity="medium"
  title="Stamping a published local time as UTC"
  description="A published departure with no offset is a local time in the zone it was announced in, not UTC. Adding a bare Z reads New York's 10:00 as 10:00 UTC — four hours early in June. Read it through startTimeZone and scheduleDelivery adds the zone's real offset."
  wrongCode={`import { scheduleDelivery } from "@northguild/gmt/transport";

scheduleDelivery([{ departure: "2024-06-15T10:00:00Z", duration: "PT1H", timeZone: "UTC" }]);
// { eta: "2024-06-15T11:00:00+00:00[UTC]",
//   legTimes: [{ arrival: "2024-06-15T11:00:00Z", localArrival: "2024-06-15T11:00:00+00:00[UTC]", dwellAfter: "PT0S" }] } — read New York's 10:00 as UTC`}
  rightCode={`import { scheduleDelivery } from "@northguild/gmt/transport";

scheduleDelivery([{ departure: "2024-06-15T10:00:00", duration: "PT1H", timeZone: "UTC" }], { startTimeZone: "America/New_York" });
// { eta: "2024-06-15T15:00:00+00:00[UTC]",
//   legTimes: [{ arrival: "2024-06-15T15:00:00Z", localArrival: "2024-06-15T15:00:00+00:00[UTC]", dwellAfter: "PT0S" }] } — 10:00 in New York, four hours later in UTC`}
  rightSpecId="scheduleDelivery"
/>

<Mistake
  severity="medium"
  title="Timing a crossing from its wall clocks"
  description="Subtracting two printed clock readings assumes both ends share one offset. On a DST night they don't: New York's fall-back makes an hour-long crossing read as zero. crossingTime reads the exact elapsed time, never the printed digits."
  wrongCode={`(Date.parse("2024-11-03T01:30:00") - Date.parse("2024-11-03T01:30:00")) / 36e5;
// 0 — both ends read 01:30, so the naive subtraction sees no time pass at all`}
  rightCode={`import { crossingTime } from "@northguild/gmt/transport";

crossingTime("2024-11-03T05:30:00Z", "2024-11-03T06:30:00Z", "America/New_York");
// { duration: "PT1H", enter: "2024-11-03T01:30:00-04:00[America/New_York]", exit: "2024-11-03T01:30:00-05:00[America/New_York]" }`}
  rightSpecId="crossingTime"
/>

<Mistake
  severity="medium"
  title="Writing an offset into a skipped hour"
  description="02:30 on 10 March 2024 never showed on a New York clock, so no offset names it. Leave the offset off and it resolves to the later instant, 03:30."
  wrongCode={`import { scheduleDelivery } from "@northguild/gmt/transport";

scheduleDelivery([{ departure: "2024-03-10T02:30:00-05:00[America/New_York]", duration: "PT1H", timeZone: "America/New_York" }], { startTimeZone: "America/New_York" });
// null — no offset names a time the clock skipped`}
  rightCode={`import { scheduleDelivery } from "@northguild/gmt/transport";

scheduleDelivery([{ departure: "2024-03-10T02:30:00", duration: "PT1H", timeZone: "America/New_York" }], { startTimeZone: "America/New_York" });
// { eta: "2024-03-10T04:30:00-04:00[America/New_York]",
//   legTimes: [{ arrival: "2024-03-10T08:30:00Z", localArrival: "2024-03-10T04:30:00-04:00[America/New_York]", dwellAfter: "PT0S" }] } — resolves to 03:30, the later instant`}
  rightSpecId="scheduleDelivery"
/>
