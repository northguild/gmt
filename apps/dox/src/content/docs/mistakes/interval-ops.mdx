---
title: Interval Operations
description: Common mistakes when working with date and time intervals in GMT.
---

GMT has two families of interval functions. The half-open `interval/` module
(`intervalsOverlap`, `intersectIntervals`, `subtractIntervals`, `sumIntervals`, …) takes
`{ start, end }` records of instant strings. The older positional functions in `plain/`,
`utc/`, `zoned/` and `unix/` take separate strings, and most of them read an interval as
closed. Most interval bugs come from mixing the two. Every output shown here is what the
function returns today.

## Mistakes

import Mistake from "../../../components/Mistake.astro";

<Mistake
  severity="high"
  title="Assuming touching intervals do not overlap in the positional functions"
  description="The positional intervalsOverlap* functions are closed [start, end]: a shared endpoint belongs to both intervals, so touching intervals overlap. Only the half-open interval/ module treats them as disjoint."
  wrongCode={`intervalsOverlapUtc("2024-01-01T09:00:00Z", "2024-01-01T17:00:00Z", "2024-01-01T17:00:00Z", "2024-01-01T18:00:00Z");
// expected false — actually true`}
  rightCode={`import { intervalsOverlap } from "@northguild/gmt";

intervalsOverlap(
  { start: "2024-01-01T09:00:00Z", end: "2024-01-01T17:00:00Z" },
  { start: "2024-01-01T17:00:00Z", end: "2024-01-01T18:00:00Z" },
); // false — half-open, they share no instant`}
/>

<Mistake
  severity="high"
  title="Reading intervalAbuts* as a shared endpoint"
  description="The positional intervalAbuts* functions are true when one interval ends exactly one unit before the other starts — one nanosecond, one day for Date, one epoch unit for Unix. Intervals that share an endpoint already overlap, so they do not abut."
  wrongCode={`intervalAbutsDate("2024-01-01", "2024-06-30", "2024-06-30", "2024-12-31");
// expected true — actually false`}
  rightCode={`intervalAbutsDate("2024-01-01", "2024-06-30", "2024-07-01", "2024-12-31"); // true

// Half-open: "abuts" is just a.end === b.start, and those intervals do not overlap
intervalsOverlap({ start: "…T09:00:00Z", end: "…T17:00:00Z" }, { start: "…T17:00:00Z", end: "…T18:00:00Z" }); // false`}
/>

<Mistake
  severity="high"
  title="Expecting intervalDifference* pieces to meet the removal exactly"
  description="The closed intervalDifference* and intervalXor* functions step one unit in from each cut, so the pieces end one nanosecond before a removal starts and begin one nanosecond after it ends. Summing those pieces is 2 ns short. subtractIntervals cuts exactly."
  wrongCode={`intervalDifferenceUtc("2024-01-01T09:00:00Z", "2024-01-01T17:00:00Z", "2024-01-01T12:00:00Z", "2024-01-01T13:00:00Z");
// [{ start: "2024-01-01T09:00:00Z", end: "2024-01-01T11:59:59.999999999Z" },
//  { start: "2024-01-01T13:00:00.000000001Z", end: "2024-01-01T17:00:00Z" }]`}
  rightCode={`import { subtractIntervals, sumIntervals } from "@northguild/gmt";

const worked = subtractIntervals(
  { start: "2024-01-01T09:00:00Z", end: "2024-01-01T17:00:00Z" },
  [{ start: "2024-01-01T12:00:00Z", end: "2024-01-01T13:00:00Z" }],
);
// [{ start: "2024-01-01T09:00:00Z", end: "2024-01-01T12:00:00Z" },
//  { start: "2024-01-01T13:00:00Z", end: "2024-01-01T17:00:00Z" }]
sumIntervals(worked); // "PT7H"`}
/>

<Mistake
  severity="high"
  title="Passing plain dates or zoneless datetimes to interval/"
  description="interval/ endpoints are instants: an offset (Z or ±HH:MM) is required. A plain date or a local datetime has no position on the timeline until a zone is named, so every function returns its sentinel for it."
  wrongCode={`intervalsOverlap({ start: "2024-01-01", end: "2024-01-02" }, { start: "2024-01-01T12:00:00", end: "2024-01-03T00:00:00" });
// false — both are invalid input, not a real answer`}
  rightCode={`import { floorToZone, intervalsOverlap } from "@northguild/gmt";

// Build local-day edges as instants first
const day = {
  start: floorToZone("2024-01-01T12:00:00Z", "day", "America/New_York"), // "2024-01-01T05:00:00Z"
  end: floorToZone("2024-01-02T12:00:00Z", "day", "America/New_York"),   // "2024-01-02T05:00:00Z"
};`}
/>

<Mistake
  severity="medium"
  title="Treating [] from mergeIntervals or subtractIntervals as an error"
  description="[] is a legitimate result — a fully covered subtraction, or a list of only empty intervals — and it is also the invalid-input sentinel. Check the inputs with isValidInterval when the difference matters."
  wrongCode={`const left = subtractIntervals(shift, removals);
if (left.length === 0) throw new Error("bad input"); // wrong when the removals cover the shift`}
  rightCode={`import { isValidInterval, subtractIntervals } from "@northguild/gmt";

if (!isValidInterval(shift) || !removals.every(isValidInterval)) {
  // genuinely invalid input
}
const left = subtractIntervals(shift, removals); // [] now means fully covered`}
/>

<Mistake
  severity="medium"
  title="Expecting sumIntervals to return days"
  description="sumIntervals returns covered time with hours as the largest unit — exactly Temporal.Instant.prototype.until with largestUnit hour. An instant has no calendar, so a day is not a fixed length and is never used."
  wrongCode={`sumIntervals([{ start: "2024-01-01T00:00:00Z", end: "2024-01-03T01:30:00Z" }]);
// expected "P2DT1H30M"`}
  rightCode={`sumIntervals([{ start: "2024-01-01T00:00:00Z", end: "2024-01-03T01:30:00Z" }]); // "PT49H30M"
sumIntervals([{ start: "2024-03-10T05:00:00Z", end: "2024-03-11T04:00:00Z" }]); // "PT23H" — New York's spring-forward day
sumIntervals([]); // "PT0S"`}
/>

<Mistake
  severity="medium"
  title="Expecting splitIntervalByUnit slices to be equal"
  description="splitIntervalByUnitDate cuts fixed amount × unit steps from the start, so the final slice is whatever remains and can be shorter. For n pieces of equal length, use intervalDivideEquallyDate."
  wrongCode={`splitIntervalByUnitDate("2024-03-15", "2024-03-20", "day", 2);
// [{ start: "2024-03-15", end: "2024-03-17" }, { start: "2024-03-17", end: "2024-03-19" },
//  { start: "2024-03-19", end: "2024-03-20" }] — the last slice is 1 day`}
  rightCode={`intervalDivideEquallyDate("2024-03-15", "2024-03-20", 2);
// [{ start: "2024-03-15", end: "2024-03-18" }, { start: "2024-03-18", end: "2024-03-20" }]`}
/>

<Mistake
  severity="high"
  title="Using intervalCount where you meant a length"
  description="intervalCount* counts the calendar units the half-open interval touches; intervalLength* measures how long it is. They agree only when the interval starts on a unit boundary and is a whole number of units long."
  wrongCode={`intervalCountDateTime("2024-01-01T23:59:00", "2024-01-02T00:01:00", "day");
// 2 — used as a duration, but the interval is two minutes long`}
  rightCode={`import { intervalLengthDateTime } from "@northguild/gmt";

intervalLengthDateTime("2024-01-01T23:59:00", "2024-01-02T00:01:00", "day");
// 0.001388888888888889`}
/>

<Mistake
  severity="medium"
  title="Expecting a zero-length interval to always count 0 or always count 1"
  description="intervalCount* counts 1 for a zero-length interval that sits mid-unit and 0 for one exactly on a unit boundary. A PlainDate always sits on a day boundary, so it counts 0 days but 1 month."
  wrongCode={`intervalCountDate("2024-01-15", "2024-01-15", "day");   // 0
intervalCountDate("2024-01-15", "2024-01-15", "month"); // 1 — not 0`}
  rightCode={`intervalCountDate("2024-01-01", "2024-01-01", "month"); // 0 — exactly on a month boundary`}
/>

<Mistake
  severity="medium"
  title="Passing an options object to intervalFromDuration*"
  description="intervalFromDuration* takes the value, an ISO 8601 duration and an anchor of start or end. Calendar units resolve against the value itself — there is no relativeTo option. A negative duration returns null rather than an inverted interval."
  wrongCode={`intervalFromDurationDate("2024-03-15", "P1M", { relativeTo: "2024-03-15" });`}
  rightCode={`import { intervalFromDurationDate } from "@northguild/gmt";

intervalFromDurationDate("2024-03-15", "P1M", "start"); // { start: "2024-03-15", end: "2024-04-15" }
intervalFromDurationDate("2024-01-31", "P1M", "start"); // { start: "2024-01-31", end: "2024-02-29" }
intervalFromDurationDate("2024-03-15", "-P10D", "start"); // null`}
/>

<Mistake
  severity="medium"
  title="Reading intervalOverlappingDays* as a closed intersection object"
  description="intervalOverlappingDays* returns a number: how many distinct calendar dates the closed intersection touches, counting both endpoints. For the shared span itself, use intervalIntersection* or intersectIntervals."
  wrongCode={`const shared = intervalOverlappingDaysDate("2024-01-01", "2024-06-30", "2024-04-01", "2024-12-31");
shared.start; // undefined — shared is 91`}
  rightCode={`intervalOverlappingDaysDate("2024-01-01", "2024-06-30", "2024-06-30", "2024-12-31"); // 1 — shared endpoint
intervalIntersectionDate("2024-01-01", "2024-06-30", "2024-04-01", "2024-12-31");
// { start: "2024-04-01", end: "2024-06-30" }`}
/>

<Mistake
  severity="medium"
  title="Calling list functions with flat arguments, or without a suffix"
  description="mergeIntervals*, intervalXorAll* and every interval/ list function take one array of { start, end } records. The positional list functions carry a type suffix — there is no bare intervalXorAll."
  wrongCode={`intervalXorAll(a, b);`}
  rightCode={`import { intervalXorAllDate, mergeIntervals } from "@northguild/gmt";

intervalXorAllDate([a, b, c]); // positional, closed, Date values
mergeIntervals([x, y, z]);     // half-open, instant strings`}
/>
