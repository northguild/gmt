description: Which runtimes ship Temporal, how the proposal stands in ECMA-262, and the GMT function for each Temporal call.

GMT is built on `@js-temporal/polyfill`, so it runs on a runtime that has no native Temporal. This page lists where Temporal is native and which GMT function matches each Temporal call.

## Where Temporal runs

Checked 2026-10-26, from the MDN browser compatibility data.

| Runtime | First version with Temporal |
| --- | --- |
| Chrome and Edge | 144 |
| Firefox | 139 |
| Node.js | 26 |
| Deno | 2.7 |
| Bun | 1.4.0 |
| Safari on macOS | Technology Preview only |
| Safari on iOS | not supported |

## Status of the specification

TC39 moved Temporal to Stage 4 on 2026-03-11. It is not yet part of ECMA-262. On 2026-10-26 the pull request that adds it, [ecma262 #3966](https://github.com/tc39/ecma262/pull/3966), was open. An earlier pull request, #3759, was closed without merging. The text of the proposal is at [tc39.es/proposal-temporal](https://tc39.es/proposal-temporal/), and the clause numbers below refer to it.

## Using both from one import

GMT re-exports `Temporal`, `Intl` and `toTemporalInstant` from its root, taken from the polyfill. Code that needs a Temporal object and a GMT function can take both from `@northguild/gmt`.

```js
import { Temporal, toTemporalInstant } from "@northguild/gmt";
```

For the results other libraries return on the same inputs, see [Behaviour of date libraries against Temporal](/compare/behaviour/). Each library has its own page: [date-fns](/migrate/date-fns/), [Luxon](/migrate/luxon/), [Day.js](/migrate/dayjs/), [Moment.js](/migrate/moment/) and [@internationalized/date](/migrate/internationalized-date/).
