## What changes

- date-fns takes and returns `Date` objects, or `TZDate` from `@date-fns/tz`. GMT takes and returns strings.
- `getMonth` counts months from 0. GMT counts them from 1 to 12, as Temporal does.
- The difference functions take the later date first, as in `differenceInCalendarDays(later, earlier)`. `diffDate` takes the earlier date first.
- Invalid input gives an `Invalid Date`, and `format` throws a `RangeError`. GMT returns `""`, `null`, `false` or `[]` instead of throwing.

```js
import { diffDate } from "@northguild/gmt/plain/calculate";

diffDate("2024-03-01", "2024-03-15", "days"); // 14
```

## Basic-format dates

`parseISO` reads `20240212`, as Temporal does. GMT's validators and parsers accept only the extended format, `2024-02-12`, which is the format of RFC 3339 §5.6, so `isValidDate("20240212")` returns `false`. This is deliberate. Convert a basic-format string before you pass it on. The behaviour matrix shows the library's result in case [M9c](/compare/behaviour/#m9c-date-fns).
