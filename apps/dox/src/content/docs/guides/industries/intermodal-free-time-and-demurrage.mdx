Free time is the money calculation in container logistics, and the first thing to know about it
is that none of its terms is a fact about the port. How many free days there are, whether the day
of discharge is free day one, and whether weekends count are set by the carrier's tariff, the
lane and the service contract. So every term is a parameter, none has a default, and what comes
back is what a demurrage or detention invoice has to state: the free time allowed, when it
started and ended, and the specific dates that were charged
([46 CFR 541.6](https://www.law.cornell.edu/cfr/text/46/541.6)).

```typescript
import { chargeableDays, demurrageClock, freeTimeExpiry } from "@northguild/gmt/intermodal";
```

The functions live in `@northguild/gmt/intermodal`, all under `@northguild/gmt/intermodal/calculate`.

## Three clocks: `demurrageClock`

Three charges run on a container, and they are routinely confused. **Demurrage** runs from
discharge from the vessel until the container leaves the terminal gate. **Detention** runs from
gate-out until the empty is returned. Terminal **storage** runs over the same window as demurrage
but is the terminal's own charge, with its own free time.
[`demurrageClock(events, scope, options?)`](/reference/intermodal/calculate/demurrageClock)
selects the start and end events for the charge you asked about, so the wrong pair can never
reach the day count.

```typescript
import { demurrageClock } from "@northguild/gmt/intermodal";

const events = [
  { type: "discharged", at: "2024-06-14T19:00:00Z" },
  { type: "available", at: "2024-06-15T12:00:00Z" },
  { type: "gatedOut", at: "2024-06-20T14:30:00Z" },
  { type: "emptyReturned", at: "2024-06-27T09:00:00Z" },
];

demurrageClock(events, "demurrage");
// { start: "2024-06-14T19:00:00Z", end: "2024-06-20T14:30:00Z" }

demurrageClock(events, "detention");
// { start: "2024-06-20T14:30:00Z", end: "2024-06-27T09:00:00Z" } — gate-out to empty return

// Some tariffs start the import clock at the availability date, which the invoice must show too.
demurrageClock(events, "demurrage", { startEvent: "available" });
// { start: "2024-06-15T12:00:00Z", end: "2024-06-20T14:30:00Z" }
```

The result is a half-open [`Interval`](/reference/types/interval/Interval), `[start, end)`, in
the caller's own strings, and feeds `chargeableDays(start, end, …)` directly. A required event
that is missing, or present twice, returns `null`: a container discharged twice is a data error,
not a choice.

```typescript
demurrageClock([{ type: "discharged", at: "2024-06-14T19:00:00Z" }], "demurrage");
// null — still in the terminal: no gate-out
```

## Which day is day one: `firstDay`

Whether the day of the triggering event counts as free day one, or free time starts the
following day, is a tariff term. The two conventions differ by a full day of charges, so
`firstDay` has no default: omit it and every function returns `null`.
[`freeTimeExpiry(clockStart, freeDays, options)`](/reference/intermodal/calculate/freeTimeExpiry)
lays the window out.

```typescript
import { freeTimeExpiry } from "@northguild/gmt/intermodal";

// A Friday afternoon discharge in New York with three free days.
freeTimeExpiry("2024-06-14T19:00:00Z", 3, {
  basis: "calendar",
  timeZone: "America/New_York",
  firstDay: "eventDay",
});
// { freeTimeStart: "2024-06-14", lastFreeDay: "2024-06-16", expiresAt: "2024-06-17T04:00:00Z" }

// The same tariff read the other way: one more day.
freeTimeExpiry("2024-06-14T19:00:00Z", 3, {
  basis: "calendar",
  timeZone: "America/New_York",
  firstDay: "nextDay",
});
// { freeTimeStart: "2024-06-15", lastFreeDay: "2024-06-17", expiresAt: "2024-06-18T04:00:00Z" }

freeTimeExpiry("2024-06-14T19:00:00Z", 3, { basis: "calendar", timeZone: "America/New_York" });
// null — firstDay has no default
```

`freeTimeStart` and `lastFreeDay` are local dates in the counting zone; `expiresAt` is the
instant free time ends, the first instant of the local day after `lastFreeDay`, as a UTC
instant.

## Days are the terminal's local days

`clockStart` is an instant (`Z`, an offset, or a bracketed zone, of which only the instant is
read), and its local date in `options.timeZone` is the event day. A container discharged at
23:00 has used a free day by 00:01 under `firstDay: "eventDay"`. Day boundaries are the zone's
real ones, the same ones [`floorToZone`](/reference/calendar/calculate/floorToZone) and
[`dwellTime`](/reference/transport/calculate/dwellTime) find: a 23- or 25-hour day is one day, a
date the zone deleted is never a free day, and a date the clock falls back into is one day.

```typescript
// 23:00 local on the 14th: the free day is over an hour later.
freeTimeExpiry("2024-06-15T03:00:00Z", 1, {
  basis: "calendar",
  timeZone: "America/New_York",
  firstDay: "eventDay",
});
// { freeTimeStart: "2024-06-14", lastFreeDay: "2024-06-14", expiresAt: "2024-06-15T04:00:00Z" }

// Santiago skipped midnight on 8 September 2024, so that day starts at 01:00.
freeTimeExpiry("2024-09-07T15:00:00Z", 1, {
  basis: "calendar",
  timeZone: "America/Santiago",
  firstDay: "eventDay",
});
// { freeTimeStart: "2024-09-07", lastFreeDay: "2024-09-07", expiresAt: "2024-09-08T04:00:00Z" }
```

The zone is the caller's fact. GMT does not resolve a port or terminal code to a time zone, and
takes an IANA identifier. A fixed offset such as `"+02:00"` is accepted, as
[`isValidTimeZone`](/reference/zoned/validate/isValidTimeZone) accepts it, but observes no DST.

## Calendar days or working days: `basis`

Most carriers count **calendar days**, so a weekend burns two free days while the terminal is
shut. Some tariffs count **working days**, usually only for detention, and then the terminal's
own weekend and holidays decide which days count. The working basis needs the terminal's
[`BusinessCalendar`](/reference/types/business-calendar/BusinessCalendar); without one it returns
`null`, because a working-day count with a guessed weekend is a wrong invoice.

```typescript
const terminal = { weekend: [6, 7], holidays: [], timeZone: "America/New_York" };

// Friday, Monday, Tuesday: the weekend does not count.
freeTimeExpiry("2024-06-14T19:00:00Z", 3, {
  basis: "working",
  timeZone: "America/New_York",
  firstDay: "eventDay",
  calendar: terminal,
});
// { freeTimeStart: "2024-06-14", lastFreeDay: "2024-06-18", expiresAt: "2024-06-19T04:00:00Z" }

// A terminal holiday on the Monday moves expiry a day.
freeTimeExpiry("2024-06-14T19:00:00Z", 3, {
  basis: "working",
  timeZone: "America/New_York",
  firstDay: "eventDay",
  calendar: { ...terminal, holidays: ["2024-06-17"] },
});
// { freeTimeStart: "2024-06-14", lastFreeDay: "2024-06-19", expiresAt: "2024-06-20T04:00:00Z" }

// A Saturday discharge: free time starts Monday under either convention.
freeTimeExpiry("2024-06-15T14:00:00Z", 2, {
  basis: "working",
  timeZone: "America/New_York",
  firstDay: "eventDay",
  calendar: terminal,
});
// { freeTimeStart: "2024-06-17", lastFreeDay: "2024-06-18", expiresAt: "2024-06-19T04:00:00Z" }

freeTimeExpiry("2024-06-14T19:00:00Z", 3, {
  basis: "working",
  timeZone: "America/New_York",
  firstDay: "eventDay",
});
// null — a working-day count needs the terminal's calendar
```

The calendar's `weekend` is ISO weekday numbers, so a Friday–Saturday terminal passes `[5, 6]`.
Its `timeZone` field is not read; `options.timeZone` is the counting zone. Both bases run on
the same walk over the zone's real local days, with the working basis simply not counting a
closed day, so the two can never disagree about where a day begins.

## Expiry is half-open, and the charged dates are listed: `chargeableDays`

[`chargeableDays(clockStart, clockEnd, freeDays, options)`](/reference/intermodal/calculate/chargeableDays)
lays free time out with the same walk and then counts the days on or after `expiresAt` that the
half-open dwell `[clockStart, clockEnd)` touched. A gate-out at exactly `expiresAt` is not a
chargeable day; one second later is. The same
[half-open rule](/guides/intervals/interval-basics/) governs every interval in the library.

```typescript
import { chargeableDays } from "@northguild/gmt/intermodal";

const tariff = { basis: "calendar", timeZone: "America/New_York", firstDay: "eventDay" };

// Out exactly as free time ends: nothing to pay.
chargeableDays("2024-06-14T19:00:00Z", "2024-06-17T04:00:00Z", 3, tariff);
// { freeDaysUsed: 3, chargeableDays: 0, expiresAt: "2024-06-17T04:00:00Z",
//   chargedDates: [], byTier: [{ from: 1, to: null, days: 0 }] }

// One second later: one charged day, and the invoice can name it.
chargeableDays("2024-06-14T19:00:00Z", "2024-06-17T04:00:01Z", 3, tariff);
// { freeDaysUsed: 3, chargeableDays: 1, expiresAt: "2024-06-17T04:00:00Z",
//   chargedDates: ["2024-06-17"], byTier: [{ from: 1, to: null, days: 1 }] }

// Out on the second free day: two free days used, none charged.
chargeableDays("2024-06-14T19:00:00Z", "2024-06-15T15:00:00Z", 3, tariff);
// { freeDaysUsed: 2, chargeableDays: 0, expiresAt: "2024-06-17T04:00:00Z",
//   chargedDates: [], byTier: [{ from: 1, to: null, days: 0 }] }
```

`chargedDates` is the list [46 CFR 541.6](https://www.law.cornell.edu/cfr/text/46/541.6)
requires a demurrage or detention invoice to print, "the specific date(s) for which demurrage
and/or detention were charged". Returning it makes the count auditable instead of asserted. On
the calendar basis with `firstDay: "eventDay"`, `freeDaysUsed + chargeableDays` is exactly
[`dwellTime`](/reference/transport/calculate/dwellTime)'s `calendarDays` for the same dwell: the
two never disagree about a midnight.

On the working basis the clock is suspended on closed days, so a weekend or holiday after expiry
is not charged either.

```typescript
chargeableDays("2024-06-14T19:00:00Z", "2024-06-24T15:00:00Z", 3, {
  basis: "working",
  timeZone: "America/New_York",
  firstDay: "eventDay",
  calendar: { weekend: [6, 7], holidays: ["2024-06-19"], timeZone: "America/New_York" },
});
// { freeDaysUsed: 3, chargeableDays: 3, expiresAt: "2024-06-19T04:00:00Z",
//   chargedDates: ["2024-06-20", "2024-06-21", "2024-06-24"],
//   byTier: [{ from: 1, to: null, days: 3 }] }
```

A tariff with no free time passes `freeDays: 0` to `chargeableDays`; every counted day is
charged and `expiresAt` is the start of day one. `freeTimeExpiry` returns `null` for `0`, because
there is no last free day to name.

```typescript
chargeableDays("2024-06-14T19:00:00Z", "2024-06-16T15:00:00Z", 0, tariff);
// { freeDaysUsed: 0, chargeableDays: 3, expiresAt: "2024-06-14T04:00:00Z",
//   chargedDates: ["2024-06-14", "2024-06-15", "2024-06-16"],
//   byTier: [{ from: 1, to: null, days: 3 }] }
```

## Tiers are day bands, not rates

Carrier tariffs escalate by day band. `tiers` names the last chargeable-day ordinal of each
band, so `[5, 10]` is days 1–5, 6–10 and 11 onward, and `byTier` says how many charged days fell
in each. Every band is returned, an empty one with `days: 0`, so your rate table lines up by
index. GMT computes days, never money.

```typescript
chargeableDays("2024-06-14T19:00:00Z", "2024-06-28T15:00:00Z", 3, { ...tariff, tiers: [5, 10] });
// { freeDaysUsed: 3, chargeableDays: 12, expiresAt: "2024-06-17T04:00:00Z",
//   chargedDates: ["2024-06-17", "2024-06-18", "2024-06-19", "2024-06-20", "2024-06-21",
//                  "2024-06-22", "2024-06-23", "2024-06-24", "2024-06-25", "2024-06-26",
//                  "2024-06-27", "2024-06-28"],
//   byTier: [{ from: 1, to: 5, days: 5 }, { from: 6, to: 10, days: 5 }, { from: 11, to: null, days: 2 }] }

chargeableDays("2024-06-14T19:00:00Z", "2024-06-28T15:00:00Z", 3, { ...tariff, tiers: [10, 5] });
// null — tiers must ascend
```

## What the invoice has to print

Since 28 May 2024 a demurrage or detention invoice on a US trade must state the allowed free
time in days, the start and end dates of free time, the container availability date for
imports or the earliest return date for exports, and the specific dates charged
([46 CFR 541.6](https://www.law.cornell.edu/cfr/text/46/541.6)). `freeDays`, `freeTimeStart`,
`lastFreeDay`, the `available` event and `chargedDates` are those fields. The invoice, dispute
and resolution deadlines around that invoice are date arithmetic on these outputs and are not
part of this layer.
