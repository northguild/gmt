Every `@northguild/*` package ships [TanStack Intent](https://intent.tanstack.com)
skill files (`SKILL.md`) inside the npm tarball. Each skill is a self-contained,
versioned bundle of guidance — API surface, naming conventions, and Temporal
patterns — routed to a specific task. Rather than hand-holding an agent through
manual `node_modules` traversal, the Intent CLI loads the relevant skill on
demand so the agent works with the right GMT methods for the job.

## Install (one time)

`intent install` writes a managed skill-loading block into `AGENTS.md` (or
`CLAUDE.md` / `.cursorrules`) at the root of your project. The block is tagged
`<!-- intent-skills:start -->` so future `intent` runs can update it in place:

```bash
npx @tanstack/intent@latest install
```

Intent auto-detects your package manager and generates the correct runner
(`npx` / `pnpm dlx` / `yarn dlx` / `bunx`) in the block it writes.

## Discover skills

When a task arises, list every available skill across installed `@northguild/*`
packages:

```bash
npx @tanstack/intent@latest list
```

Sample output:

```
@northguild/gmt
  - gmt-basics
  - gmt-arithmetic
  - gmt-timezone
  - gmt-integration

@northguild/gmt-eslint
  - first-time-setup
  - migration-refactor
  - ci-enforcement
```

## Load a skill

Load the skill that matches the task into the agent's context:

```bash
npx @tanstack/intent@latest load @northguild/gmt#gmt-basics
```

The lint packages use the same `load <package>#<skill>` form:

```bash
npx @tanstack/intent@latest load @northguild/gmt-eslint#first-time-setup
npx @tanstack/intent@latest load @northguild/gmt-oxlint#migration-refactor
npx @tanstack/intent@latest load @northguild/gmt-biome#ci-enforcement
```

## Map tasks to skills

For projects that want explicit routing, pass `--map` to bind a task keyword to a
skill so `intent list` highlights the right match automatically:

```bash
npx @tanstack/intent@latest install --map "basics=gmt-basics" --map "arithmetic=gmt-arithmetic" --map "timezone=gmt-timezone" --map "lint=first-time-setup"
```

## Allowlist skills

To restrict which skills an agent may load, add an `intent.skills` allowlist to
your `package.json`:

```json
{
  "intent": {
    "skills": ["@northguild/gmt#gmt-basics", "@northguild/gmt#gmt-timezone"]
  }
}
```

## Stale check (optional)

Verify that loaded skills reference non-outdated source docs and regenerate the
managed block:

```bash
npx @tanstack/intent@latest stale
```

## Consumer-facing skills

These are the skills a consumer reaches for day to day. Each is a lightweight
routing pointer (~30–60 lines) that carries the core rules and points the agent
to the installed package's `README.md` and source JSDoc for full API signatures,
locale matrices, and code examples — not an API dump:

### `@northguild/gmt`

| Slug | Task area | Points to |
| --- | --- | --- |
| `gmt-basics` | Current values, parse, format, relative time, compare, validate | `README.md`, `src/plain/`, `src/zoned/` |
| `gmt-arithmetic` | Add/subtract, diff, durations, interval range math | `README.md`, `src/plain/`, `src/duration/`, `src/plain/interval/` |
| `gmt-timezone` | Zoned get/format/convert, DST disambiguation | `README.md`, `src/zoned/`, `src/unix/`, `src/utc/` |
| `gmt-integration` | Cache keys, router/query params, lint package selection | `README.md`, lint package READMEs |

> **Skills are routing pointers, not API documentation.** When a skill is loaded,
> the agent should read the installed package's `README.md` and the JSDoc of the
> specific function it intends to call for full signatures, locale matrices, and
> code examples. The skill files carry the core rules and common pitfalls; the
> README carries the details.

### `@northguild/gmt-eslint` / `gmt-oxlint` / `gmt-biome`

| Slug | Guide | Description |
| --- --- | --- | --- |
| `first-time-setup` | [Lint Package Selection](/guides/integration/linting/) | Install and wire the lint package; verify Date-ban rules active |
| `migration-refactor` | — | Migrate existing code off `Date` APIs |
| `ci-enforcement` | — | Set up CI enforcement of lint rules |

## Contributor skills

Skills intended for library maintainers — **not** shipped in the npm tarball
(excluded via `.npmignore`). These are for contributing to `@northguild/gmt`
itself:

| Slug | Description |
| --- | --- |
| `issue-creation` | Create feature requests with proper details for maintainers |
| `pr-contribution` | Contribute improvements via pull requests |
| `new-method-implementation` | Implement or extend a gmt API in `packages/gmt/src` |
| `unit-test-generation` | Write or update gmt unit tests |
| `api-expansion-workflow` | Handle feature requests for missing gmt functionality |

Load a contributor skill only when the user is contributing to `@northguild/gmt`
itself:

```bash
npx @tanstack/intent@latest load @northguild/gmt#issue-creation
```
