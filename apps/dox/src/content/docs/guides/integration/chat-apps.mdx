The site runs one remote, read-only [MCP](https://modelcontextprotocol.io/) server. It offers
the tool of every page under [Tools](/tools/). A tool runs the same gmt functions as its page
and answers in the same JSON, so a chat app, a browser agent and the page agree. The fields of
the answer (`ok`, `tool`, `input`, `result`, `notes` and `link`) are described in
[Page Tools for Browser Agents](../browser-agents/). The `link` opens the page on the live site
with the call's values filled in.

Nothing here changes anything. A tool reads its input, runs a function and answers.

## The address

The server speaks Streamable HTTP. Send it a `POST`; it answers `GET` and `DELETE` with `405`.
Write the address with no trailing slash.

| Address                                        | Lists                      |
| ---------------------------------------------- | -------------------------- |
| `https://northguild.dev/gmt/api/mcp`           | Every tool                 |
| `https://northguild.dev/gmt/api/mcp/transport` | Only the `transport` tools |

The second row is an example. Use any industry id from the [Tools](/tools/) index in place of
`transport`. An id the server does not know gets a `404` that names the scopes it does know.

Add a scope when you can. A chat app sends the description of every listed tool to the model
on every turn, so a short list leaves more room for your own conversation and gives the model
fewer tools to choose between.

## Add it to your app

Each step below was checked against the vendor's own documentation on 2026-11-19. Menus move
often, so check the vendor's page if a name differs. The server needs no sign-in, so choose "no
authentication" wherever an app asks.

### Claude

Claude connects to a remote server from Anthropic's servers, so the address must be public, and
this one is. On a Pro or Max plan, open **Customize > Connectors**, choose **+ Add**, then **Add
custom connector**. Enter a name and the address, then continue. Where Claude asks how people
sign in, choose **No sign in**. On a Team or Enterprise plan an owner adds the connector under
**Organization settings > Connectors**, and members then connect it. Turn it on for a
conversation from the **+** button, under **Connectors**.
Source: [Get started with custom connectors using remote MCP](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

### ChatGPT

Use ChatGPT on the web. Go to [ChatGPT Plugins](https://chatgpt.com/plugins), choose the plus
button, then **Add custom MCP server**. Enter a name and the **Server URL**, choose **No
authentication**, accept the risk warning and select **Create as a plugin**. Install the plugin,
then type `@` and its name in the prompt box. Your workspace's permissions and security
settings can block custom servers, so ask an admin if the option is missing.
Source: [Add custom MCP server](https://platform.openai.com/docs/guides/developer-mode).

### Claude Code

```bash
claude mcp add --transport http gmt-tools https://northguild.dev/gmt/api/mcp
```

Source: [Connect Claude Code to tools via MCP](https://code.claude.com/docs/en/mcp).

### Cursor

Add the server to `mcp.json`, or to **Customize** in Cursor:

```json
{
  "mcpServers": {
    "gmt-tools": {
      "url": "https://northguild.dev/gmt/api/mcp"
    }
  }
}
```

Source: [Model Context Protocol (MCP)](https://cursor.com/docs/context/mcp).

### VS Code

For Copilot, run **Chat: Open Customizations**, select **MCP Servers**, then **Add Server**,
choose **HTTP** and enter the address. Choose **Global** > **Copilot Global** to use it in every
workspace (`~/.copilot/mcp-config.json`). To share it with a team, put it in `.mcp.json` at the
workspace root:

```json
{
  "mcpServers": {
    "gmt-tools": {
      "type": "http",
      "url": "https://northguild.dev/gmt/api/mcp"
    }
  }
}
```

A `.vscode/mcp.json` file uses a different layout (`servers`) and is for VS Code's older Local
setup.
Source: [MCP configuration reference](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).

## What the server sees

The server sees the input of each call. It uses your IP address to count calls for the rate
limit, keeps that count in the Worker's memory for one rate-limit window and never stores it.
There is no sign-in and no session. The Worker has logging turned off, so it keeps no request
log either.

## Limits

- **Too many calls** return HTTP `429` with a `retry-after` header and
  `{ "error": "rate-limited", "retryable": true }`. Wait that long, then retry.
- **A request body over 64 KiB** returns `413`.
- **The tools are read-only.** They never change anything.
- **A refusal is an ordinary result.** Input that breaks a tool's rules comes back as
  `{ "ok": false, "error": "invalid-input" }` with the issues listed, so the model can read it
  and correct its call.
