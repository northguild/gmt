Use these functions to combine intervals, remove time from an interval, and total up how
much time a set of intervals covers.

## Merge a list

`mergeIntervals` collapses a list into the fewest sorted intervals that do not overlap.
Input order does not matter. Because the intervals are half-open, touching intervals
join. Intervals separated by even one nanosecond stay apart:

```typescript
import { mergeIntervals } from "@northguild/gmt";

mergeIntervals([
  { start: "2024-01-01T13:00:00Z", end: "2024-01-01T17:00:00Z" },
  { start: "2024-01-01T09:00:00Z", end: "2024-01-01T12:00:00Z" },
  { start: "2024-01-01T12:00:00Z", end: "2024-01-01T13:00:00Z" },
]);
// [{ start: "2024-01-01T09:00:00Z", end: "2024-01-01T17:00:00Z" }]
```

An empty interval that touches or lies inside a merged run is absorbed into it. One that
touches nothing is dropped, since it covers no time.

## Subtract windows

`subtractIntervals(from, remove)` returns the parts of `from` that no removal covers.
Cuts land exactly where a removal starts and ends, with no one-unit step:

```typescript
import { subtractIntervals } from "@northguild/gmt";

const shift = { start: "2024-01-01T09:00:00Z", end: "2024-01-01T17:00:00Z" };

subtractIntervals(shift, [{ start: "2024-01-01T12:00:00Z", end: "2024-01-01T13:00:00Z" }]);
// [{ start: "2024-01-01T09:00:00Z", end: "2024-01-01T12:00:00Z" },
//  { start: "2024-01-01T13:00:00Z", end: "2024-01-01T17:00:00Z" }]

subtractIntervals(shift, [{ start: "2024-01-01T08:00:00Z", end: "2024-01-01T18:00:00Z" }]);
// [] — everything removed
```

`remove` may be unsorted and overlapping. A removal that only touches `from` removes
nothing.

## Sum covered time

`sumIntervals` returns the length of the union as an exact ISO 8601 duration. Overlapping
time counts once, and empty intervals add nothing:

```typescript
import { sumIntervals } from "@northguild/gmt";

sumIntervals([
  { start: "2024-01-01T09:00:00Z", end: "2024-01-01T13:00:00Z" },
  { start: "2024-01-01T12:00:00Z", end: "2024-01-01T17:00:00Z" },
]); // "PT8H" — the overlapping hour counts once

sumIntervals([{ start: "2024-01-01T00:00:00Z", end: "2024-01-03T01:30:00Z" }]); // "PT49H30M"
sumIntervals([{ start: "2024-03-10T05:00:00Z", end: "2024-03-11T04:00:00Z" }]); // "PT23H"
sumIntervals([]); // "PT0S"
```

Hours are the largest unit. The output is exactly what TC39 `Temporal.Instant.prototype.until`
returns with `largestUnit: "hour"`, because an instant has no calendar to say how long a day
is. That is also why the New York day across the spring-forward change is `PT23H`. The total
is summed in `bigint` nanoseconds, so it stays exact at any size.

Composed together, these answer the question every realm asks: how much of this interval
fell inside the allowed windows?

```typescript
const breaks = [{ start: "2024-01-01T12:00:00Z", end: "2024-01-01T13:00:00Z" }];

sumIntervals(subtractIntervals(shift, breaks)); // "PT7H" — worked time
```

## The positional functions

The pairwise `intervalUnion*`, `intervalDifference*` and `intervalXor*`, and the list forms
`mergeIntervals*` and `intervalXorAll*`, are half-open too. Touching intervals join, and
every cut lands exactly on an input's own `start` or `end`, with no one-unit step:

```typescript
import {
  intervalDifferenceDate,
  intervalDifferenceUtc,
  intervalUnionDate,
  intervalXorAllDate,
  intervalXorDate,
  mergeIntervalsDate,
} from "@northguild/gmt";

intervalUnionDate("2024-01-01", "2024-07-01", "2024-07-01", "2025-01-01");
// { start: "2024-01-01", end: "2025-01-01" } — touching intervals join
intervalUnionDate("2024-01-01", "2024-06-30", "2024-07-01", "2024-12-31");
// null — 30 June lies in neither interval

intervalDifferenceDate("2024-01-01", "2024-12-31", "2024-06-01", "2024-07-01");
// [{ start: "2024-01-01", end: "2024-06-01" }, { start: "2024-07-01", end: "2024-12-31" }]

intervalDifferenceUtc("2024-01-01T09:00:00Z", "2024-01-01T17:00:00Z", "2024-01-01T12:00:00Z", "2024-01-01T13:00:00Z");
// [{ start: "2024-01-01T09:00:00Z", end: "2024-01-01T12:00:00Z" },
//  { start: "2024-01-01T13:00:00Z", end: "2024-01-01T17:00:00Z" }]

intervalXorDate("2024-01-01", "2024-07-01", "2024-04-01", "2025-01-01");
// [{ start: "2024-01-01", end: "2024-04-01" }, { start: "2024-07-01", end: "2025-01-01" }]

mergeIntervalsDate([
  { start: "2024-01-01", end: "2024-01-10" },
  { start: "2024-01-05", end: "2024-01-15" },
]);
// [{ start: "2024-01-01", end: "2024-01-15" }]

intervalXorAllDate([
  { start: "2024-01-01", end: "2024-01-10" },
  { start: "2024-01-05", end: "2024-01-15" },
  { start: "2024-01-08", end: "2024-01-20" },
]);
// [{ start: "2024-01-01", end: "2024-01-05" }, { start: "2024-01-08", end: "2024-01-10" }, { start: "2024-01-15", end: "2024-01-20" }]
```

`intervalXorAll*` returns the maximal runs covered by an odd number of the inputs, sorted by
start, so two identical intervals cancel to `[]`. `intervalDifferenceUtc` above returns the
same pieces as `subtractIntervals` on the same shift: they meet the lunch break exactly, and
together with it they cover the shift with nothing counted twice.
