Use these functions for three questions: "is this instant in the range?", "do these
two ranges share any time?" and "what part of this range falls inside that one?"

## Overlap and intersection, half-open

`intervalsOverlap(a, b)` is `a.start < b.end && b.start < a.end`. It is `true` exactly
when `intersectIntervals(a, b)` is not `null`, so the two can never disagree:

```typescript
import { intersectIntervals, intervalsOverlap } from "@northguild/gmt";

const morning = { start: "2024-01-01T09:00:00Z", end: "2024-01-01T13:00:00Z" };
const afternoon = { start: "2024-01-01T12:00:00Z", end: "2024-01-01T18:00:00Z" };
const evening = { start: "2024-01-01T18:00:00Z", end: "2024-01-01T22:00:00Z" };

intervalsOverlap(morning, afternoon); // true
intersectIntervals(morning, afternoon);
// { start: "2024-01-01T12:00:00Z", end: "2024-01-01T13:00:00Z" }

intervalsOverlap(afternoon, evening); // false — they touch at 18:00 and share no instant
intersectIntervals(afternoon, evening); // null
```

Empty intervals (`start === end`) follow the same rule:
- An empty interval strictly inside another overlaps it, and the intersection is that
  empty interval.
- An empty interval at an edge does not overlap.

`intervalContains(interval, t)` is `start ≤ t < end`:

```typescript
import { intervalContains } from "@northguild/gmt";

intervalContains(morning, "2024-01-01T09:00:00Z"); // true
intervalContains(morning, "2024-01-01T13:00:00Z"); // false — the end is excluded
intervalContains(morning, "2024-01-01T04:00:00-05:00"); // true — the same instant as 09:00Z
```

## Clamp to a window

`clampInterval(interval, bounds)` is `intersectIntervals(interval, bounds)` under a name
that reads better when `bounds` is a fixed window such as a business day:

```typescript
import { clampInterval } from "@northguild/gmt";

const businessDay = { start: "2024-01-01T09:00:00Z", end: "2024-01-01T17:00:00Z" };

clampInterval({ start: "2024-01-01T08:00:00Z", end: "2024-01-01T12:00:00Z" }, businessDay);
// { start: "2024-01-01T09:00:00Z", end: "2024-01-01T12:00:00Z" }
```

The output endpoints are always the caller's own strings. When both arguments spell the
same instant differently, such as `04:00:00-05:00` and `09:00:00Z`, the first argument's
spelling wins. No specification covers this tie. GMT chose it because a rule based on
position is deterministic without inventing a canonical spelling.

## The positional functions

The positional `intervalContains*`, `intervalsOverlap*` and `intervalIntersection*`
functions in `plain/`, `utc/`, `zoned/` and `unix/` follow the same half-open rule, so the
end is outside and touching intervals do not overlap:

```typescript
import {
  intervalContainsDate,
  intervalContainsUtc,
  intervalIntersectionDate,
  intervalsOverlapDate,
} from "@northguild/gmt";

intervalContainsUtc("2024-01-01T09:00:00Z", "2024-01-01T17:00:00Z", "2024-01-01T17:00:00Z");
// false — the end is excluded

intervalsOverlapDate("2024-01-01", "2024-07-01", "2024-07-01", "2025-01-01");
// false — the first interval ends before 1 July

intervalIntersectionDate("2024-01-01", "2024-07-01", "2024-04-01", "2025-01-01");
// { start: "2024-04-01", end: "2024-07-01" }

intervalIntersectionDate("2024-01-01", "2024-07-01", "2024-07-01", "2025-01-01");
// null — touching intervals share no date
```

With a fourth argument, `intervalContains*` tests an inner interval instead of a point,
and `intervalEngulfs*` is the same test under another name. The inner interval must lie
within the outer one and overlap it, so it may end at the outer `end`, but an empty inner
interval at `end` is not contained:

```typescript
intervalContainsDate("2024-01-01", "2024-12-31", "2024-03-01", "2024-09-01"); // true
intervalContainsDate("2024-01-01", "2025-01-01", "2024-07-01", "2025-01-01"); // true — same end
intervalContainsDate("2024-01-01", "2025-01-01", "2025-01-01", "2025-01-01"); // false — empty, at the end
```

`intervalAbuts*` is true when one interval's `end` equals the other's `start`, in either
order. Any gap, even one nanosecond, means they do not abut, and an empty interval abuts
nothing:

```typescript
import { intervalAbutsDate, intervalAbutsUtc } from "@northguild/gmt";

intervalAbutsDate("2024-01-01", "2024-07-01", "2024-07-01", "2025-01-01"); // true
intervalAbutsDate("2024-01-01", "2024-06-30", "2024-07-01", "2024-12-31"); // false — 30 June is in neither

intervalAbutsUtc(
  "2024-01-01T09:00:00Z",
  "2024-01-01T12:00:00Z",
  "2024-01-01T12:00:00.000000001Z",
  "2024-01-01T17:00:00Z",
); // false — 1 ns apart
```
