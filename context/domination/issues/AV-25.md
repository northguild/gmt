# AV-25 — Aviation: Flight legs, day offset and block time

**Scope:** Flight leg timing across timezones, with the day offset schedules actually publish.

## Gap

Aviation has the hardest timezone-crossing problem in transport, and the first draft's `flightLeg` could not express its most basic output: a flight departing 23:40 and arriving 06:15 arrives on a **different local date**, and every published schedule carries that as a day indicator (`+1`, `−1`, `+2`). Returning only a duration loses it.

## Scope

- `packages/gmt/src/aviation/calculate/flightLeg.ts`:
  - `flightLeg(departure: string, arrival: string, options: { departureZone: string, arrivalZone: string }): { duration: string, localDeparture: string, localArrival: string, dayOffset: number, offsetChange: string } | null` — `dayOffset` is the signed local-date difference between departure and arrival.
- `packages/gmt/src/aviation/calculate/blockTime.ts`:
  - `blockTime(offBlocks: string, onBlocks: string): string` — Chocks-off to chocks-on, as an ISO duration.
  - `airTime(takeoff: string, landing: string): string` — Wheels-up to wheels-down. Always shorter than block time; conflating the two is a recurring reporting error.
- `packages/gmt/src/aviation/convert/scheduledTime.ts`:
  - `scheduledTime(isoString: string, airportZone: string): string` — Scheduled UTC to airport local time for display.

## Design notes

- **`dayOffset` is computed from local dates, not from duration.** A two-hour eastbound flight can cross a local date boundary; an eleven-hour westbound flight can arrive on the same local date it departed. Deriving the offset from elapsed time is wrong in both directions.
- **`zonesCrossed` is removed.** The original spec returned a count of "timezone transitions", which is not well defined for a flight — an aircraft overflies zones it never enters, and the count depends on the route rather than the schedule. `offsetChange`, the UTC offset difference between the two airports at those two instants, is unambiguous and is what schedules need.
- `airportZone` is a caller-supplied IANA zone. GMT does not map IATA or ICAO codes to zones — see [../painpoints.md](../painpoints.md) on parked registries.
- Aviation operates on UTC ("Zulu"). Local times exist for passenger display and for crew-duty rules only; every internal instant stays UTC.

## What gmt provides (do not re-implement)

- `transitTime` / `etaAtZone` from TRAN-8 — leg arithmetic
- `spanMs` from CORE-2 — block and air time
- `floorToZone` from CORE-5 — local date derivation for `dayOffset`
- `convertUtcToZoned` — timezone conversion

## Verification

- An overnight leg departing 23:40 returns `dayOffset: 1`
- An eastbound trans-Pacific leg crossing the date line returns `dayOffset: -1`
- A leg departing and arriving on the same local date returns `dayOffset: 0` regardless of duration
- `offsetChange` is correct where one airport observes DST and the other does not
- A leg operated either side of a DST transition returns the same duration and a different `offsetChange`
- `airTime` is strictly shorter than `blockTime` for the same flight
- Invalid zone returns the sentinel
- Full IANA timezone coverage
- `pnpm run validate` stays green
