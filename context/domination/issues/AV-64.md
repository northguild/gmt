# AV-64 — Aviation: AIRAC cycles and aeronautical publication deadlines

**Scope:** The 28-day AIRAC cycle every aeronautical database, chart and procedure change is published against, and the distribution deadlines that hang off each effective date.

## Gap

Under ICAO Annex 15, operationally significant changes to aeronautical information take effect only on "a series of common effective dates at intervals of 28 days, including 8 November 2018" (§6.2.1) — the AIRAC system. Information "shall not be changed further for at least another 28 days after the effective date" (§6.2.2); it must be distributed "so as to reach recipients at least 28 days in advance of the effective date" (§6.2.3, a Standard; the Note adds that AIS units distribute at least 42 days ahead); "Implementation dates other than AIRAC effective dates shall not be used for pre-planned operationally significant changes" (§6.2.5); and for major changes the Recommendation is 56 days (§6.2.7). Every navigation database in every aircraft is loaded by cycle, and the arithmetic is small: one anchor date the Standard itself supplies, and a 28-day stride.

The two-digit-year-plus-sequence identifier (`2601` for the first cycle of 2026) is how much of the industry refers to a cycle, but it is **not** in Annex 15; state AIS calendars write it differently (`2601`, `01-26`, or a 0-based index). It is offered as a convention with the sequence number as the primitive.

([ICAO Annex 15, 16th edition, Chapter 6 §6.2](https://www.icao.int/sites/default/files/safety/CAPSCA/PublishingImages/Pages/ICAO-SARPs-(Annexes-and-PANS)/an15_1.pdf); effective dates cross-checked against three state AIS calendars: [Uganda CAA AIC A17/25](https://aim.caa.co.ug/pdf/airac-dates.pdf), [ENNA Algeria](https://www.sia-enna.dz/airac-calendar.html), [Sakaeronavigatsia](https://ais.airnav.ge/en/airac-cycles))

## Scope

- `packages/gmt/src/aviation/get/airacCycle.ts`:
  - `airacCycle(isoDate: string): { effectiveFrom: string, effectiveTo: string, year: number, sequenceInYear: number, identifier: string } | null` — The cycle a date falls in; `effectiveTo` is the next effective date (half-open). `identifier` is the `YYNN` convention built from the other two fields.
  - `nextAiracDate(isoDate: string): string` — The first effective date strictly after the input.
  - `airacDatesInYear(year: number): string[]` — Thirteen or fourteen dates.
  - `airacIdentifierToDates(identifier: string): { effectiveFrom: string, effectiveTo: string } | null` — `'2601'` to its dates under the `YYNN` convention.
- `packages/gmt/src/aviation/calculate/airacDeadlines.ts`:
  - `airacDeadlines(effectiveDate: string): { receiptBy: string, distributionBy: string, majorChangeReceiptBy: string, nilNotificationBy: string }` — 28 days (§6.2.3 Standard), 42 days (§6.2.3 Note), 56 days (§6.2.7 Recommendation) and one cycle (§6.2.4 NIL notification) before the effective date, each labelled with its status in the JSDoc.

## Design notes

- **The anchor is the Standard's own: 8 November 2018.** Annex 15 §6.2.1 names that date, so no data table and no data-subpath record is needed; every effective date is `anchor + 28n` days. Verified against the published 2025–2027 calendars (13 cycles each: 23 Jan 2025, 22 Jan 2026, 21 Jan 2027 as the first cycles), all Thursdays.
- **The identifier is a convention and says so.** `sequenceInYear` counts cycles whose effective date falls in the calendar year (13 in most years, 14 in some); `identifier` is the `YYNN` string the airline and database-vendor world uses, and the JSDoc records that Annex 15 does not define it and that some states publish other forms.
- **Dates are UTC dates.** AIRAC effective dates are dates; the functions take and return ISO dates and the JSDoc says so, so nobody applies a zone.
- **Deadlines carry their normative weight.** The 28-day receipt rule is a Standard; 42 days is a Note describing AIS practice; 56 days is a Recommendation. The result names each so a compliance report does not promote a Note to a rule.
- AIRAC governs published information. NOTAM validity and schedules (AV-28) are the mechanism for everything urgent or temporary that falls between cycles; the two stories reference each other and neither implies the other.

## What gmt provides (do not re-implement)

- `addDate` / `subtractDate` / `diffDate` — the 28-day stride and the deadline offsets
- `getYear` from `plain/` — the identifier's year component
- `isValidDate` — input validation

## Verification

- `airacCycle('2018-11-08')` returns that date as `effectiveFrom` with `effectiveTo` `'2018-12-06'`
- `airacCycle` on the day before an effective date returns the previous cycle, asserted at the half-open boundary
- `airacDatesInYear(2025)`, `(2026)` and `(2027)` each return 13 dates matching the published state calendars exactly, beginning 23 January, 22 January and 21 January
- `airacCycle('2026-01-22')` returns `year: 2026, sequenceInYear: 1, identifier: '2601'`; `airacIdentifierToDates('2601')` round-trips
- `airacDeadlines('2026-01-22')` returns `receiptBy: '2025-12-25'`, `distributionBy: '2025-12-11'`, `majorChangeReceiptBy: '2025-11-27'`, `nilNotificationBy: '2025-12-25'`
- A date before the 2018 anchor still resolves (the stride extends backwards) and the JSDoc says the anchor is the Standard's reference, not the system's start
- A malformed identifier or an invalid date returns the sentinel
- `pnpm run validate` stays green
