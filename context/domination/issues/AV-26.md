# AV-26 — Aviation: Schedule seasons, SSIM dates and connections

**Scope:** IATA scheduling seasons, SSIM date formats, days of operation, and minimum connect time.

## Gap

Airline scheduling is organised around seasons, and GMT could not express one. Every schedule, slot allocation and timetable is filed against a season, and the season boundaries are deliberately aligned to European DST — so they move each year and cannot be hardcoded as dates.

Alongside that, SSIM carries its own date and day-of-operation encodings that no general date library parses.

## Scope

- `packages/gmt/src/aviation/get/scheduleSeason.ts`:
  - `getScheduleSeason(isoString: string): { season: 'NS' | 'NW', year: number, code: string, startsAt: string, endsAt: string }` — The IATA season containing a date. `code` is the conventional form, e.g. `'NS26'`, `'NW25'`.
  - `seasonBounds(season: 'NS' | 'NW', year: number): { startsAt: string, endsAt: string }`
- `packages/gmt/src/aviation/parse/ssimDate.ts`:
  - `parseSsimDate(value: string): string | null` — `'01JAN26'` (`DDMMMYY`) to an ISO date.
  - `formatSsimDate(isoString: string): string` — Inverse. Month is uppercase three-letter English.
- `packages/gmt/src/aviation/parse/daysOfOperation.ts`:
  - `parseDaysOfOperation(value: string): number[] | null` — SSIM day string (`'1234567'`, with blanks or dots for non-operating days) to ISO weekday numbers.
  - `operatingDatesBetween(from: string, to: string, days: number[]): string[]`
- `packages/gmt/src/aviation/calculate/connectionTime.ts`:
  - `connectionTime(inboundArrival: string, outboundDeparture: string, options: { airportZone: string, minimumConnect: string }): { available: string, meetsMinimum: boolean } | null`

## IATA scheduling seasons

- **Northern Summer (NS)** runs from the last Sunday in March to the last Saturday in October.
- **Northern Winter (NW)** covers the remainder of the year.
- Boundaries coincide with EU daylight saving transitions, which is why they are computed rather than tabulated.
- Written with the trailing two year digits, e.g. `NS26`; a winter season spanning a year boundary is often written `NW25/26`.

([Simple Flying](https://simpleflying.com/iata-summer-winter-schedule/))

## Design notes

- **Season boundaries are computed from the DST rule, not stored.** Hardcoding dates guarantees the library is wrong every year.
- **`DDMMMYY` month abbreviations are English and locale-independent.** They must not go through `Intl`, or a non-English default locale silently breaks parsing. This is an explicit exception to the library's locale-aware formatting rules and belongs in the JSDoc.
- **`minimumConnect` is a parameter.** MCT varies by airport, terminal pair, domestic/international status and carrier, and no bundled table would be correct.
- The two-digit SSIM year needs a century rule. Document the pivot explicitly rather than inheriting a runtime default.

## What gmt provides (do not re-implement)

- `getIsoWeekDate` / `floorToZone` from CORE-5 — weekday and boundary arithmetic
- `resolveLocal` from CORE-4 — season boundary instants
- `spanMs` from CORE-2 — connection time

## Verification

- `getScheduleSeason` returns `NS` for a date in April and `NW` for a date in November
- A date on the last Sunday in March falls in `NS`; the preceding Saturday falls in `NW`
- Season boundaries coincide with the EU DST transition for the year under test, asserted across at least three different years
- `parseSsimDate('01JAN26')` round-trips through `formatSsimDate`
- `parseSsimDate` is unaffected by the ambient locale, asserted against the full locale matrix
- Lowercase or malformed month abbreviations return the sentinel
- `parseDaysOfOperation('1.3.5..')` returns `[1, 3, 5]`
- `connectionTime` returns `meetsMinimum: false` when available time is below the minimum
- `pnpm run validate` stays green
