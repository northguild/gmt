# HLTH-94 — Decisions

Part of [HLTH-94](../HLTH-94.md).

Settled by the owner. They are the current rules for this code.

- The three functions are `parseFHIR`, `isValidFHIR` and `formatFHIR`, in `healthcare/{parse,validate,format}/`, with the types `FhirDateTime`, `FhirDateType`, `FhirPrecision` and `FhirFormatOptions` in `types/fhir.ts` and the patterns `fhirDate`, `fhirDateTime` and `fhirInstant` in `regex/fhir.ts`. No subpath is new. Sentinels are `null`, `""` and `false`; none throws, for a value of any type. Every call is constant work, so there are no bench rows. `isValidFHIR` has the three overloads `isValidEpcisEventTime` has.
- `parseFHIR` and `isValidFHIR` both call the internal core `readFhirValue` in `internal/fhirDateTime.ts`, and `formatFHIR` calls it for its final check. A public function never calls another public function ([coding-standards § Loop cost](../../../coding-standards.md#loop-cost)). So `isValidFHIR(v, "dateTime")` is true exactly when `parseFHIR(v)` returns a value, `"date"` adds a precision of day or coarser, and `"instant"` adds second or fraction; the agreement rows in the tests keep them in step. The file is not in the `internal/index.ts` barrel, because it imports `toOffsetInstant`, which reads the barrel at module top.
- The core reads the form with `fhirDateTime` and the values with Temporal (`overflow: "reject"`). `coding-standards.md` carries the scoped exception, as it does for the HL7 and EDI grammars. A second of `60` is checked through `LEAP_SECOND_STEPS`, `parseUtcReading` and `taiOfUtc`, which are `isLeapSecond`'s own core, never through `toOffsetInstant`, which refuses every `:60`.
- Precision is kept, never padded. `parseFHIR("2024-06")` is a month with the offset `""`. The precisions are `year`, `month`, `day`, `second` and `fraction`; FHIR has no hour or minute, so a time without seconds is invalid in every type. Comparing two partial values is FHIRPath's rule, not GMT's.
- A time with no zone is invalid as every type. Unlike HL7 v2 it is not the sender's local time, so no function resolves a wall time and "Disambiguation: none" is stated in the JSDoc.
- A second of `60` is valid only on an inserted leap second. A fraction of more than nine digits, `24:00`, the year `0000`, a day the month lacks and an offset past `±14:00` are refused. `Z`, `+00:00` and `-00:00` read as the offset `+00:00`, and `value` keeps the spelling sent.
- The three patterns are FHIR R4's own, taken from the `regex` extension on `.value` of the `date`, `dateTime` and `instant` StructureDefinitions, JSON-decoded, with `^…$` added. They are shape only, as `epcisEventTime` is: `fhirDateTime` accepts `2024-02-30`, `fhirDate` accepts `2023-02-29` and `fhirInstant` accepts `2017-12-31T23:59:60Z` and a ten-digit fraction. A string `isValidFHIR` accepts always matches the type's pattern, and not the other way round. Each `source` is asserted against a copy kept in the test.
- `formatFHIR` reads the same ISO 8601 and RFC 9557 forms `formatHL7` reads, through `isoHl7Form` and `isoHl7Precision`; `formatHL7` is not reshaped. It cuts and never rounds, and the default precision is the one written, or day under `date`. It returns `""` for a finer `precision` than the value carries, a precision the type does not allow, a second of `60`, a time with no offset under `dateTime` or `instant` at second precision, a zone with no offset, and a minute or hour value that is not cut to a day or coarser.
- `formatFHIR` never zero-fills: a minute or hour input reaches FHIR only when cut to a day or coarser, because adding `:00` would claim a second the input does not carry.
- Under `date`, `formatFHIR` writes the wall-clock date at the input's own offset: `2024-06-15T23:30:00-05:00` is `2024-06-15`. A caller who wants the UTC date passes the `Z` form. The designator is written as the input spells it, except that a `Z` read through a bracketed zone writes that zone's offset (`…Z[Europe/Berlin]` writes `+02:00`). Every result is checked by `readFhirValue` before it is returned, so every non-empty result is valid, and every valid value without a second of `60` formats to itself.
