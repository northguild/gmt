# Tier 6: Dox, the chat (surface, pipeline, client)

Part of [built/index.md](index.md). Widget tools the brain calls: [tier-6-chat-tools.md](tier-6-chat-tools.md). Brains, budget, traps: [tier-6-brains.md](tier-6-brains.md). Operator steps: [tier-6-runbooks.md](tier-6-runbooks.md).

## Shape

- One surface: `/dox` (`src/pages/dox.astro`, `<DoxPage client:load />`), `noindex`, reached from the header's "Chat with Dox" button (`aria-current="page"` there). The header is Astro with no JavaScript, so no React reaches another page except the deck's Dox frame (WCAG 2.2 SC 3.2.3). There is no every-page dock. Page context follows through the referrer.
- Stack: the AI SDK (`ai`, `@ai-sdk/react` `useChat`) and vendored AI Elements in `src/components/ai-elements/`. Install one with `npx ai-elements@latest add <name>` (bare `npx ai-elements@latest` installs all 48). The CLI rewrites imports from `components.json`, so the repo keeps its `~/` alias and has no `@/`. Streamdown renders replies; code blocks keep copy and drop download.
- `message.tsx` imports `katex/dist/katex.min.css` so it loads with the island only. Without it formulas render twice and `\sqrt` svgs overflow.
- Tailwind v4 exists only in the island (`reference/design-system.md`).
- Worker (`apps/dox/worker/`): `POST /gmt/api/chat`, `GET /gmt/api/brains`; everything else goes to `ASSETS`. The `.md` prompt sources load as Text modules (a `wrangler.jsonc` rule; Vitest mirrors it with a `markdownAsText` plugin). `createChatHandler` takes vocabulary, core rules, model factory, ledger and clock as injected dependencies.
- Keys live only in Worker secrets and `.dev.vars`, never in `dist/` or a response. No provider flag restricts a model to a corpus: grounding is the prompt, the context and the refusal instruction.

## Retrieval

- Chunks are built at `astro build` into `/retrieval-chunks.json` (`src/lib/retrieval/corpus.ts`): one per reference entry and one per guide `##` heading. Guides load through `import.meta.glob`, not `fs` (`fs` breaks once Astro bundles the endpoint). The Worker fetches chunks same-origin through the Cache API (`fetch-chunks.ts`).
- `fetchChunks` keeps the parsed array in memory for the Cache API TTL (300 s) and returns the same array until it expires; `search.ts` memoises the MiniSearch index in a `WeakMap` keyed on that array. A new array always gets a fresh index; `searchChunks` stays pure.
- A type chunk adds each member's name and description; a function chunk adds `Name: description` for each documented type its signature names (`function-chunks.ts`).
- Search is MiniSearch BM25 (`src/lib/retrieval/search.ts`) with a stopword list, `MIN_RELEVANCE_SCORE` and up to 15 chunks. The index splits camelCase identifiers and keeps the whole one; only the index side splits. The threshold is tuned to this corpus: re-verify after material changes to the corpus or boosts. Typo tolerance stops at two edits. A question of three or more topic terms (numbers excluded) returns nothing when any of them matches no chunk at all, unless it carries on-topic evidence: a word that names at least five gmt functions (read from the corpus), an IANA zone city (`Intl.supportedValuesOf`, so Lagos and Singapore count and Mumbai does not), or a clock or calendar token. One unknown word is enough, because the guides use so many everyday words that an off-topic sentence has few. Zone-id endings that are mostly everyday words or names (`EVERYDAY_WORDS`: Center, Casey, Easter, Jersey and others) are not zone cities. A reader's own nouns (a boss, a ferry) therefore never count against a question about time. A zone city also adds `timezone` to the query, since such a question rarely says it. A question naming two zone cities is a zone conversion whatever else it says: `convertZonedToZoned` is placed fourth among the hits, and `prepareTurn` gives the skills covering it a top-rank vote, so the timezone skill is chosen beside any skill the other words pull in. Shorter queries are never gated. Tried and dropped: a per-chunk coverage rule (long, real questions spread their words over many chunks) and the unknown-word gate with no evidence (it dropped real questions that named a city or noun the guides lack).
- Namespace bias, not a filter: `DoxChat` sends the same-origin referrer (`src/lib/page-context.ts`) and `worker/namespace-from-page.ts` turns `/reference/<ns>/...` or `/guides/<ns>/...` into a bias.
- Corpus counts on the empty screen are generated (`scripts/build-corpus-counts.ts`) and checked by `corpus-summary.test.ts`.

## Request pipeline (`worker/index.ts`, `worker/chat-handler.ts`)

| Step | Failure |
| --- | --- |
| Method | `405` |
| Burst limiter, key `chat:<clientId>`, per isolate, 20 per 60 s | `429` + `Retry-After` |
| JSON body | `400` |
| Envelope (zod) + `safeValidateUIMessages` with the real tool set; roles `user`/`assistant` only | `400` |
| Sanitise invisible characters, then apply length and conversation caps | `400` |
| Per-visitor daily cap (KV, hashed IP; dev cookie exempt) | `429` |
| No configured brain | `500` |
| Retrieve, assemble prompt | mapped error, never a raw upstream payload |
| Open the stream, then in-request failover, writing transient `data-status` per brain | pool spent or every brain busy: transient `data-refusal` |
| Write the retrieval trace part, then merge `toUIMessageStream` (`sendReasoning: false`, `onError` on both layers) | mapped error text |

- `checkRateLimit(key, now, { max, windowSeconds })` (`worker/rate-limit.ts`) keeps one bucket per key in a module-scope `Map`: per isolate, blunt protection. Prefixes keep counts apart: `chat:`, `canada:` (`CANADA_RATE_LIMIT`, 20 per 60 s, `src/lib/canada-clock-change.ts`), `morocco:` (`MOROCCO_RATE_LIMIT`), `sunshine-protection-act:` (`SUNSHINE_ACT_RATE_LIMIT`, `worker/sunshine-protection-act.ts`).
- Clock-change endpoints (`GET /gmt/api/canada-clock-change`, `.../morocco-clock-change`, `worker/canada-clock-change.ts`, `worker/morocco-clock-change.ts`; Morocco is a config over `handleClockChangeCheck`) compute from the library at request time, answer `cache-control: no-store`, answer other methods `405` with `Allow: GET, HEAD, POST`, and over the limit `429` + `retry-after` + `{ error, retryable: true }`. Year scans and `now`-free tables are memoised per isolate (a GET otherwise costs about 80 scans, too much CPU for the Free plan). `last` and `next` search UTC years Y-1..Y+1. Morocco's POST zone allowlist is `Africa/Casablanca` and `Africa/El_Aaiun`.
- `deploy-smoke.mjs` runs against the deployed Worker (tz 2026e), never `wrangler dev` (its local workerd carries tz data older than 2026c). Canada checks five probe offsets against 2026e. Morocco's offsets are literals cited to tzdb 2026c; a later tzdb change fails the row on purpose. It runs four calls to the `morocco:` bucket per run (probe, HEAD, PUT answering 405, a `STORED_MAX_LINES` POST that must answer 200 with `truncated: false`; Error 1102 is a failure) plus the page and the hashed `timezone-boundaries` `license: "ODbL-1.0"`. Sunshine Protection Act: GET (`no-store`, a row per zone of `us-region-zones.json`, offset form not value), HEAD, PUT `405` with `Allow: GET, HEAD`, the page, and the hashed `timezone-boundaries-us` and `state-boundaries-us` files (56 shapes), each found from the hashed URL the deployed tool page requests (`hashedAsset`).
- The stream opens before a brain is chosen. Each step arrives as a transient `data-status` part and shows in the pending card.
- Badge counts arrive in the stream: after a brain answers, the Worker writes a transient `data-usage` part (`USAGE_PART_TYPE`, `withRecordedRequest` in `worker/brains-payload.ts`); `DoxChat` hands it to `useBrains().apply`. Re-reading `/api/brains` after the answer races the ledger write (KV can take a minute); a refusal or stream error still re-reads it.
- A refusal is a transient `data-refusal` part carrying `{ status, payload }` (`RefusalData`, `src/lib/chat-types.ts`), passed to `classifyChatError`. Transient parts never enter a message, so a refused request leaves no empty turn (`DoxChat.progress.test.tsx`). Anything known before the stream opens is a plain HTTP error. A pool spent or all brains busy during the answer is HTTP 200 with the refusal in the stream: anything watching the endpoint must handle that.
- System prompt (`worker/system-prompt.ts`), eight sections in order, pinned by `system-prompt.test.ts`: Persona and scope, Standing order (the prompt-injection boundary), Linking rules (only this answer's retrieved URLs), Vocabulary, Core rules (`worker/core-rules.md`, `core-rules.test.ts`), Retrieved context, Available tools, Refusal instruction. When tools are offered, one closing sentence follows the Refusal section: a question that matches a `Call when` line is covered by that tool and is never a refusal. `callWhen()` writes each tool's `Call when` once.
- The prompt is cut to the question. Vocabulary (`worker/select-vocabulary.ts`): each consumer skill's frontmatter `sources:` is matched against the top ten chunks; a chunk votes by rank, split evenly between skills that list it; the best skill always goes in, another joins at half the best score if it fits `VOCABULARY_BUDGET_CHARS` (16,000); "When to load" and "References" sections drop; none matching gives "(none for this question)". Chunks (`worker/fit-chunks.ts`): at most 10 and 24,000 characters, best first, the best always in; the linking allowlist and trace come from the same list. A chunk no skill lists votes for nothing: when a skill's guide coverage looks thin, add the page or folder to its `sources:`.

## Chat client

- Transport: `DefaultChatTransport` with `prepareSendMessagesRequest`, sending `sendableHistory` (`src/lib/chat-history.ts` drops assistant turns that got no token), `pageContext` and the picked brain.
- Link hardening (`link-components.tsx`, `resolve-href.ts`): `rehype-harden` plus a `components.a` override, which is the authority. A relative path in the route manifest is a link; an absolute URL on our origin has its origin stripped then re-checked; a relative path not in the manifest, a GitHub anchor or a `SKILL.md` heading is plain text; external `https`/`http`/`mailto` on an allowlisted origin is a link; `javascript:`, `data:` and unparseable are dropped. Bold phrases are never auto-linked.
- Timeouts (`use-idle-timeout.ts`): 90 s to first output (restarted by each progress line), then 30 s between chunks. Each brain has its own start deadline (`BRAIN_START_TIMEOUT_MS`).
- A rate limit, refused send or stall renders a warning (`chat-warning.tsx`), never a message; `retryable` drives "Try again".
- Composer: a real `<textarea>` from `prompt-input.tsx`. The vendored file defers `form.reset()` to the success paths so a refused send keeps the reader's text; keep that on any AI Elements re-sync.
- The accuracy note (`.gmt-hive-accuracy-note`) cites the test count from `src/data/gmt-stats.json`, formatted in `en-US`. Below 60rem the note and `.gmt-hive-licence` are `display: none` and `ChatInfo.tsx`'s info button opens both in one native `popover="auto"`; CSS picks the form so the server render is right. `AccuracyNote` and `LicenceNote` are the popup's single source, `LicenceDisclosure` the footer's.
- `RetrievalTrace.tsx` shows chunk count and titles and the brain that answered. The Worker times each stage (`worker/timing.ts`); the part is written twice with one `id` (`RETRIEVAL_PART_ID`) and the SDK replaces it in place. The same numbers go to the log as one `dox-timing` line beside `dox-usage`: read them before tuning anything.
